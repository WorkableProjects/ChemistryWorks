## Build
### Backend (`Code.gs` → `VERSION = '4.0.0'`)
1. **Admin auth** `requireAdmin_(body)` used by EVERY admin action instead of the bare ADMIN_KEY compare:
   - If `body.idToken` present: verify it exactly like `verifyStudent_` (reuse/factor the token check: audience = client id, issuer, expiry, `email_verified`), lower-case/trim the email, and look it up in the **Admins** sheet → `{ ok: true, email, role, via: 'google' }`; not on the list → error `not_admin`; bad token → `invalid_token`.
   - Else if `body.adminKey` equals the `ADMIN_KEY` script property (if set) → `{ ok: true, email: '', role: 'admin', via: 'key' }` (upgrade period).
   - Else `unauthorized` (keep the existing error string the client already handles, check the code).
2. **Admins sheet** `Email | Role | Added by | Added at`. Read per request (cache ≤ 60 s with `CacheService` is optional), emails trimmed + lower-cased, blank rows ignored, roles `owner`/`admin` (anything else → `admin`). If the sheet is missing or has no emails: create it and seed from script property `ADMIN_EMAILS` (comma list; first = owner). If still empty, only ADMIN_KEY works.
3. **Admin actions** (owner only for writes): `whoami` (any admin: returns `{ email, role, via }`), `listAdmins`, `saveAdmin { email, role }` (add or change role), `removeAdmin { email }`. Refuse removing yourself and removing the last owner (`last_owner`, `cannot_remove_self`). Key-based callers count as owner only if there is no owner yet (document it).
4. **Log sheet** `Time | Admin | Action | Target | Details` appended by every admin **write** action (publish, delete test, saveGrade, releaseAll, allowRetake, saveAdmin, removeAdmin…). Admin = the verified email, or `ADMIN_KEY` when via key. Add admin action `getLog { limit }` (newest first, default 100).
5. **"Graded by"**: when `saveGrade` is called by a Google admin, record their email as graded-by if the client sent none.
6. `ping` returns `{ version: '4.0.0' }` (already returns VERSION).
7. Keep every existing action and its response shape working with `adminKey` (backwards compatible).

### Client
1. `js/lib/admin-session.js`: implement the Google part. `hasAdminAuth()` = admin key set OR a confirmed admin (session flag `adminConfirmed` = the email confirmed by `whoami`, only valid while `getUser()?.email` matches and `getIdToken()` is non-empty). `adminRequestAuth()` returns `{ idToken }` (fresh, via `getIdToken()`) when confirmed, plus `adminKey` when set.
2. `js/lib/api.js`: every admin call merges `adminRequestAuth()` into the POST body (keep the `adminKey` parameter working for callers/tests that pass it explicitly — explicit wins). Add `whoAmI`, `listAdmins`, `saveAdmin`, `removeAdmin`, `getLog`. Token expiry: if an admin call fails with `invalid_token`, call `getFreshIdToken()` once and retry (never prompt for a password).
3. **Admin gate** (`js/app.js` `adminGate`), behind `feature('adminAccounts')`: when on and Google sign-in is configured, the gate first tries the signed-in Google user → `whoAmI` → confirmed admin opens the panel with no password and no access-code prompt. Not signed in → offer "Sign in with Google" (reuse `renderGoogleButton`) plus a small "Use access code instead" link to the existing code flow. Not on the list → clear message + the access-code fallback. When the flag is off: behaviour unchanged.
4. **Settings → Admins** (`js/views/admin/admins.js`, mounted from `settings.js`; owner only, hidden for others/when flag off): list admins, add by email + role, change role, remove (with confirm), errors shown inline. **Settings → Activity log**: the latest 100 log rows in a table.
5. **Version check** (`js/lib/version-check.js`, called from `app.js` when the admin panel opens): `pingBackend()`; if the backend version is lower than `SITE_VERSION` (semver compare; unit-test the compare), show an admin banner/toast "The Apps Script backend is version X; this site is 4.0.0. Update Code.gs: …" with the 3 upgrade steps. Never shown to students. Failure to ping = no banner.
6. `builder.js`: replace the direct `load('adminKey'…)` gate (publish button) with `hasAdminAuth()` / `adminRequestAuth()`; nothing else in builder.
