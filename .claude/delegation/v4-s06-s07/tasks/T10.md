## Build (all client-side, no backend changes; ship behind `feature('teacherTools')` only where a part is unfinished — finished tools are visible)
0. Replace every `load('adminKey', '', 'session')` in your owned files with `adminKey()` / `hasAdminAuth()` from `js/lib/admin-session.js` (gate checks use `hasAdminAuth()`; api calls keep passing `adminKey: adminKey()`; api.js will merge any Google token itself).
1. **Insights** (new admin tab in `admin.js`, view `insights.js`): pick a test → score distribution (histogram, 10% buckets, inline SVG or CSS bars), average, median, average time spent; per question: % correct, average points, most-chosen wrong answer for `mcq`/`multi`/`truefalse`, a "Review" flag when < 40% correct. Click a question → every student's answer for it. **All math in pure exported helpers in `stats.js`** with unit tests that match a hand calculation on a small fixture. Data from the same `fetchResults` the grading view uses (reuse its row normalization). Charts follow the design tokens (teal bars `--brand-teal`, text tokens), accessible (table fallback / aria-labels).
2. **Grade by question** (`grade-by-question.js`, entered from grading: a "By question" toggle next to the student list): choose a test + question → one row per student with their answer (reuse the diagram rendering grading.js uses) and a points input + comment; J/K or ↑/↓ moves between students, number keys set points; "Save" calls the same `saveGrade` with the **full grades object for that submission** (merge the one question's points into that student's existing grades so other questions are untouched) — must write the same rows as the per-student view.
3. **Comment bank** (`comments.js` + `comment-view.js`): saved reusable comments per device in `localStorage` (`cw:commentBank`), optional per-question rubric (criteria + points) stored with the bank keyed by test code + question id; one-click insert into the grading comment box (per-student and by-question views); add/edit/delete in a small manager modal.
4. **Bulk tools** in the grading list: checkboxes per row + select all (visible rows) → bulk **Release**, **Un-release** (if an existing action supports it; else omit and note), **Allow retake** — implemented by looping the existing single-row actions with a progress indicator and a summary toast; no delete.
5. **Print test** (`print-test.js`, action in the library per test): paper version: student copy (no answers) and answer key, versions A/B; reuse the PDF/export renderer and `print.css`; opens the browser print dialog like the existing export.
6. **Duplicate / versions** (`js/lib/versions.js` pure helpers + library actions): "Duplicate" → copy with a new code (suggest `CODE-2`, validate unique against the library list) opened in the builder as a draft (use the builder's existing load/`setBuilderTest` API — read-only for you; call it, don't edit builder.js); "Version B" → same test with questions and options shuffled by a fixed seed (`seededShuffle` from ui.js), code suffixed `B`. Unit-test the helpers (deterministic, answer keys remapped correctly for shuffled options in mcq/multi/matching/ordering).
7. **Gradebook export**: add a "per-question columns" option to the existing CSV export (pure helper in `stats.js`, unit-tested).
