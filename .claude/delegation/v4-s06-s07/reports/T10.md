## Deviations / decisions
1. Existing `duplicate-<code>` button is unchanged and still produces `CODE_COPY`, because `test/e2e/admin.test.mjs` asserts `CHEM201_COPY`. The spec's `CODE-2` flow is a new button `duplicate-new-<code>` ("Duplicate with a new code"): modal with the suggested `CODE-2`, validated for format and uniqueness against bundled + drafts + published codes, then opens the builder via the existing `openInBuilder` -> `setBuilderTest`. If you prefer to replace the old button, change the E2E expectation.
2. Fixed a latent bug in `normalizeRow` (stats.js): it overwrote status `Extra attempt` with Auto-graded / Needs grading, so extra attempts were never recognised. Extra attempts now keep their status. Insights and bulk tools depend on it. All existing unit tests still pass.
3. Un-release and Release are implemented through the existing `saveGrade` (`release: false/true`, resending the row's existing grades and teacher note), since `releaseAll` is per test only. Side effect, same as unticking "release" in the per-student view: an Auto-graded row becomes status Graded. Release only applies to Graded/Auto rows not yet released; Un-release only to released rows; Allow retake uses `allowRetake`. No delete anywhere.
4. Insights does its own `fetchResults` (module cache) instead of sharing grading's cache, to avoid a circular import. Rows go through the same `normalizeRow`.
5. Version B: question order is shuffled inside each section (sections and unsectioned questions keep their place); option/left/right/items orders are shuffled; ids and `correctAnswer` are unchanged (keys are id-based, so they stay valid by construction, which the tests verify through `gradeQuestion`). Ordering items are never left already sorted. Code is `CODE-B` (`CODE-B2` when taken); title gets " (Version B)".
6. Print test: only types that make sense on paper (mcq, multi, truefalse, matching, ordering, numeric, formula, sigfigs, short, open, fillblank) get a real layout; drawing/graph/etc. types print the question with an answer box and a note. The answer key uses the existing `correctAnswerText`. It has its own print routine (modelled on `printSubmission`) because `export-view.js` is not mine; it reuses `#print-root`, `print.css` and the `export-*` classes.
7. Comment-bank rubric criteria show as checkboxes under the comment box and fill the points (clamped to the question max in the per-student view). Comments and rubrics are device-local in `cw:commentBank`.
