## Security notes
- A token present in the request means the Google path only. An unlisted email gets `not_admin` even if a valid `adminKey` is also in the body. A bad token gets `invalid_token`. There is no fallback to the key.
- `ALLOW_UNVERIFIED_EMAIL` never grants admin, because admin auth does not use that path.
- Token verification is factored out of `verifyStudent_` into `verifyIdToken_` with identical checks: audience, issuer, expiry, `email_verified`, and `ALLOWED_DOMAINS`.
- A key caller is `role: 'admin'`, and counts as owner only while the Admins sheet has no owner.
- `saveAdmin` validates the email with a regex that must start alphanumeric and excludes `=`, so formula injection into the sheet is blocked. Log values go through `text_`.

## Deviations / decisions
- With no token and no `ADMIN_KEY`, the error stays `admin_key_not_configured`, because an existing test asserts it.
- `ALLOWED_DOMAINS` also applies to admin tokens. This is the safest choice, but a teacher whose domain is not in the list is locked out of Google admin sign-in. Add the domain to `ALLOWED_DOMAINS`, or use the key.
- `saveAdmin` with an explicit invalid role returns `invalid_role`. A missing role defaults to `admin`.
- `removeAdmin` also deletes duplicate sheet rows for the same email.
- `saveGrade` by a Google admin overwrites a stored graded-by with their email whenever `gradedBy` is omitted or blank.
- The version-check banner is also gated by `feature('adminAccounts')`. Otherwise every 3.0.0 backend would show a banner while v4 is unfinished, and it adds a ping to the admin open that could disturb existing E2E.
- Skipped, as the task allowed: Drive `addEditor` sharing. It is mentioned in DEPLOYMENT.md as not built.
- Settings -> Admins shows only to owners. It asks `whoami` and renders nothing otherwise. The Activity log shows to any confirmed admin or key holder.

## Manual steps for Dutch
1. Paste the new Code.gs into Apps Script and save.
2. Set the script property `ADMIN_EMAILS` (first email = owner). `GOOGLE_CLIENT_ID` must already be set.
3. Run `setup` once. It creates the Admins and Log tabs and seeds Admins.
4. Deploy > Manage deployments > Edit > New version > Deploy.
5. Check `?action=ping` reports 4.0.0.
6. Turn on `FEATURES.adminAccounts` in `js/config.js`, or use `?features=adminAccounts`, to try it.
7. After everyone is on the list, delete the `ADMIN_KEY` property.
