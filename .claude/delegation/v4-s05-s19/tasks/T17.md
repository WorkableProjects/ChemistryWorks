# T17 = S15: Games II + XP/badges + assigned practice + leaderboard client (wave B)
Read ../PLAN.md, then `docs/v3/v4.0plan.md` **V4-04** (Reaction Lab, Molecule Builder, Periodic Puzzle, Daily Element;
Progress and rewards; Class leaderboard; acceptance). Builds on T15 (games I, `gameOptions`). Owns: see PLAN.md (T17 row).
- New games (original designs; keyboard-operable — "drag" also works by click/keyboard): Reaction Lab (balance/reaction
  + built-in reaction list), Molecule Builder (atoms → target formula/shape), Periodic Puzzle (tiles into an empty table
  by clues; timed or relaxed), Daily Element (one daily challenge from element data; streak).
- `js/lib/xp.js`: XP per game, levels, badges (≥ 8 badges incl. "10 in a row", "Noble gas master"), cosmetics (flask
  colours, badge frames — original art via CSS/SVG), personal history (last 10 rounds) — localStorage per student
  (`cw:xp:<email>`); pure + unit-tested.
- Assigned practice: test JSON `practice: [{ game, target, due? }]` → `js/views/practice-card.js` component
  `practiceCard(user, tests) -> Node|null` that T18's landing/dashboard mounts (report the mount line).
- Leaderboard client `js/lib/leaderboard.js`: only when `test.gameMode && test.gameOptions.leaderboard`; send only the
  final capped score with the ID token; names first name + last initial or generated nickname list ("Brave Boron");
  picker + end-screen top 10 + own rank. Backend actions arrive in T21 (`submitGameScore`, `getLeaderboard`): call them
  through a small adapter and treat `unknown_action` as "leaderboard unavailable" (render nothing).
Tests: unit (xp, badges, nickname list, score caps, leaderboard off → no network), E2E `test/e2e/v4-games-2.test.mjs`.
