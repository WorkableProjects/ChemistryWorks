## Decisions already made
**Orbital widget**
- Layout: one row per sublevel from `sublevelsFor(q)`, **highest energy at the top** (energy diagram
  convention), with a vertical "Energy ↑" axis label on the left; each row = sublevel label (monospace, e.g.
  `2p`) + its boxes side by side. Box = `button` `data-testid="orbital-box-<sub>-<i>"`, `data-state` =
  `''|'u'|'d'|'ud'` (use `empty` for ''), `aria-label = boxLabel(sub, i, state)`.
- Each box shows ↑ and/or ↓ arrows as text glyphs or SVG (spin is conveyed by arrow direction, never colour).
- Click / Enter / Space cycles `BOX_STATES` (`'' → 'u' → 'ud' → 'd' → ''`). Shift-click or right-click goes
  backwards. Keys: `ArrowUp` sets/adds spin-up, `ArrowDown` adds spin-down (so ↑ then ↓ = 'ud'),
  `Backspace`/`Delete`/`0` empties. Arrow Left/Right move focus between boxes in the row (roving focus not
  required; plain tab order is fine). Touch: buttons ≥ 44×44 px.
- Store via `api.set(q.id, isOrbitalAnswered(q, next) ? next : undefined)` where next is the normalized map.
- Live count `p[data-testid="orbital-count"][aria-live=polite]`: "N electrons placed".
- Static `orbitalDiagram`: same layout, non-interactive spans, compact; works at size 'sm' for grading lists.
**Structure charges (only when `q.studentCharges === true`; otherwise behaviour and DOM unchanged)**
- Do not pre-draw skeleton charge brackets (`chargeMarks`) when `studentCharges` — the student draws them.
- Toolbar under the board: toggle button "Brackets" `data-testid="structure-bracket"` `aria-pressed`;
  overall charge stepper: `structure-charge-down` (−), value `structure-charge-value` (shows e.g. "1−", "0",
  "2+" using `chargeLabel(n,{explicit:true})` or "0"), `structure-charge-up` (+); range ±MAX_CHARGE.
  Charge without brackets is allowed (stored) but drawn next to the structure.
- Formal charges: a "Formal charges" mode toggle is NOT used. Instead each atom gets a small stepper rendered
  in a list below the board: for each atom a row "N" `[−] value [+]` with testids `structure-fc-<atomId>-down`,
  `structure-fc-<atomId>` (value), `structure-fc-<atomId>-up`; aria-labels like "Formal charge on O 2: 1−".
  Atom clicks on the board keep adding lone pairs as today.
- Drawing: brackets = the existing bracket path style around the whole drawing, overall charge as a
  superscript outside the right bracket (`chargeLabel`, unicode minus); formal charges drawn in a small circle
  near the upper-right of the atom symbol (e.g. "+", "−", "2−"), **as text** — visually distinct from lone-pair
  dots and from the overall charge (circle outline). Never colour-only.
- Stored answer: `normalizeStructureAnswer(q, …)` already includes the charge fields; reuse `store()`.
**Results page (`results.js`)**
- Group the review list using `groupQuestions(test)`: before the first item of each section render
  `h3.results-section` (`data-testid="results-section"`) with title and calculated points (earned/total when
  scores are shown); unsectioned items first without a heading. Keep every existing testid.
- Orbital rows: "Your answer" shows `orbitalDiagram(q, r.givenAnswer, {label:'Your orbital diagram'})` plus
  the text; the correct-answer block for any `r.manual` question is labelled "Sample answer" (orbital: show
  `orbitalDiagram(q, q.sampleAnswer)` only when a sampleAnswer exists; otherwise hide the block).
- Structure with `studentCharges`: your answer uses `structureDiagram` (now with charges); the key is shown
  under "Reference answer" (not "Correct answer") since it is teacher graded.
- Pending (needsGrading) rows already show "Your teacher will grade this answer." — keep.
