## Decisions already made
**Library counts**
- On refresh, if gasUrl + adminKey exist, call `fetchSubmissionCounts` once (in parallel with the other
  loads). Every library item (bundled, drafts, published) shows a stat
  `h('span', { class: 'adm-stat', dataset: { testid: 'submission-count-<CODE>' } }, icon('users' or an existing icon), '3 submissions' | '1 submission' | '0 submissions')`.
  Counts map keys are uppercase codes; missing code → 0.
- When counts can't be loaded (no backend/key, or error) show nothing for counts (no fake zeros) — the
  published section already explains how to connect. Counts only ever render inside the admin view (which is
  behind the admin gate + key), never on student screens.
- Narrow layouts: the stat must wrap with the others and never push/cover the action buttons (check at 390px).
**Student feedback**
- Landing (signed-in student): a card "Your submitted tests" (`data-testid="past-results"`) listing
  `getLocalResults()` filtered to `student_email === user.email` (case-insensitive), newest first, max 20:
  title, code, submitted date, and a button `view-feedback-<submission_id>` "View feedback". Hidden when empty.
- New view `feedback` (`js/views/feedback.js`, `render(root, ctx, { payload })`), registered in app.js the same
  way as `results`; `ctx.navigate('feedback', { payload })`. It shows the app header, test title, and:
  - If `!config.GAS_WEB_APP_URL` → message "Feedback isn’t available on this site." (`feedback-unavailable`).
  - Calls `fetchFeedback({ gasUrl, submissionId: payload.submission_id, studentEmail: user.email })`.
    Loading skeleton; error → `feedback-error` with the message and a Retry button.
  - `released:false` → `feedback-pending`: "Your teacher hasn’t released grades and comments for this test yet."
  - `released:true` → `feedback-released`: final score `feedback-score` ("8.5 / 12 (70.8%)" — numbers in
    monospace), released date, then the per-question list built from `payload.responses` with the teacher's
    grades applied via `applyGrades(payload.responses, fb.grades)`: question number + text (`richText`),
    your answer text, points `x / max`, and when `fb.comments[qid]` exists a "Teacher comment" block
    `feedback-comment-<qid>` rendered with `commentBody`. Try `loadTest(payload.test_code, { config })` to group
    the list under section headings (`feedback-section`); on failure show the flat list.
  - Comments are shown ONLY from a released response; never read them from anywhere else.
  - A Back button returns to landing. Call `renderMath` after rendering.
