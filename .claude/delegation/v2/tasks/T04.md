## Decisions already made
1. **Score controls per question**: buttons `grade-full-<qid>`, `grade-half-<qid>`, `grade-zero-<qid>`
   (Half = max/2 rounded to 2 decimals) set the existing `points-<qid>` input. Remove the old silent clamp-on-
   blur; instead validate on input with `validatePoints`: invalid → `aria-invalid="true"`, a message element
   `points-error-<qid>` (`role="alert"`) with the error, red outline plus the text (not colour alone), and the
   Save buttons stay enabled but saving shows a toast "Fix the highlighted points first." and focuses the
   first invalid input. The total (`grade-total`) ignores invalid entries.
2. **Manual vs auto**: use `res.manual` (fallback: `MANUAL_TYPES.includes(res.type)` for old rows without the
   field) — never the type alone, because a `structure` can be manual. Auto-graded rows show
   "Auto: 1.5" as today; when the entered value differs → a pill `override-<qid>` "Override · auto 1.5"
   (icon + text). Saved grade map still only contains manual answers + real overrides + previously saved ids
   (keep existing `currentGrades()` semantics).
3. **Comments**: under each question a "Comment for student" textarea `comment-<qid>` (maxlength
   `MAX_COMMENT_CHARS`), a tiny formatting hint ("**bold**, *italic*, - lists, links"), and a live preview
   `comment-preview-<qid>` rendered with `commentBody(text)` (hidden when empty). Initial value from
   `row.comments[qid]`. On save send `comments: cleanComments(map)` (empty comments are dropped → removing
   the text deletes the comment). Comments never change points.
4. **Release**: a checkbox `release-grade` "Release grade & comments to student" next to the Save buttons,
   initially checked iff `row.released_at`. Save sends `release: checkbox.checked`. Status line shows
   "Released <date>" (`data-testid="released-status"`) or "Not released — the student sees no comments yet".
   After save, update the cached raw row with `res.grade.comments` and `res.grade.released_at`.
   List view: add a "Released" column (✓ text "Yes"/"—").
5. **Test definition for diagrams/sections**: when the grader opens, call
   `loadTest(row.test_code, { config: CONFIG, includeDrafts: true })` once per code (cache in module state;
   failures → null, silently). With a test: group cards under section headings
   (`data-testid="grade-section"`, title + calculated points) in canonical order, and render diagrams in the
   "Student" answer cell: orbital → `orbitalDiagram(q, res.givenAnswer, { size: 'sm' })`, structure →
   `structureDiagram(q, res.givenAnswer, { size: 'sm' })`, lewis → `lewisDiagram(q.element, res.givenAnswer)`;
   always keep the text (`givenAnswerText`) below the diagram. Without a test: today's text-only view,
   ordered as stored, sections derived from `res.sectionId` are not available → no headings.
6. **Export button** `export-pdf` in the grader toolbar: if there are unsaved changes, toast "Save the grade
   first" and stop; else `printSubmission({ row, test, includeComments: !!row.released_at })`; if not
   released, first show an info toast "Comments are left out until you release the grade." then print.
