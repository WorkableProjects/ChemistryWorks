# T01: Split-screen reference pane + sections in the student runner (V2-02, V2-04 runner part)

**Agent:** executor-sonnet · **Wave:** 1 · **Depends on:** wave 0 (done)

## Goal
Students taking a test see (1) section headings + instructions above the first question of each section and
(2) when the test has `references`, a resizable, collapsible reference pane beside the questions (periodic
table, text, image) that never disturbs answers, timing, navigation or submission.

## Decisions already made
1. **Sections in the runner.** `test.questions` is already in canonical order (normalizeTest). In `render()`,
   when `test.shuffleQuestions` is true, shuffle *within each group* of `groupQuestions(test)` (seeded with the
   existing `seededShuffle(list, seed + groupKey)`), never across groups. Each question card whose question is
   the first of a section gets a section header rendered above the card's head inside the card:
   `h('header', { class: 'q-section', dataset: { testid: 'section-header', sectionId } }, h('p',{class:'q-section__title'}, title), instructions ? richText(instructions,'div','q-section__instr') : null, h('span', {class:'q-section__pts'}, `${points} pts`))`.
   In focus mode it therefore shows on the first question of the section; in scroll mode it heads the group.
   Additionally, every card of a sectioned question shows a small "Part A …" pill in its head
   (`dataset.testid = 'section-pill'`). The navigator drawer groups tiles under section titles
   (keep every existing `nav-item-<id>` testid and class behaviour).
2. **Reference pane** lives in `js/views/reference-pane.js`:
   `export function referencePane(test, { storageKey }) -> { el, destroy() } | null` (null when
   `test.references` is empty). Layout (in runner.js): wrap the existing `main.runner-main` and the pane in a
   `div.runner-split` (`data-testid="runner-split"`); questions left, pane right.
   - Pane root: `aside.ref-pane` `data-testid="reference-pane"`, `aria-label="Reference materials"`, with
     `data-collapsed="true|false"`. Clearly distinct from questions (own background `--bg-sunken`, heading
     "Reference", border).
   - Tabs (only when >1 reference): `role=tablist`; each tab `button role=tab` `data-testid="ref-tab-<refId>"`,
     `aria-selected`, arrow-key navigation between tabs; panels `role=tabpanel`. Title from `referenceTitle`.
   - Collapse toggle `button` `data-testid="ref-toggle"` `aria-expanded`; collapsed = a slim vertical rail
     (wide screens) / a closed bar (narrow) that still shows the toggle. Keyboard shortcut: `R` toggles the pane
     (add it to the runner's existing keyboard handler + shortcuts modal; ignore when typing in an input).
   - Resize handle between questions and pane: `div role="separator" aria-orientation="vertical"
     tabindex="0"` `data-testid="ref-resizer"`, `aria-valuenow` = pane width %, `aria-valuemin=20`,
     `aria-valuemax=60`; pointer drag (pointer events → works for mouse and touch) and ←/→ keys (5% steps).
     Width stored as a CSS custom property `--ref-w` on `.runner-split`.
   - Remember `{ collapsed, width, tab }` with `save()` under `storageKey` = `refpane:<CODE>` (local).
   - Responsive: ≥ 1000px wide → side by side (pane open by default). Below 1000px → the pane stacks above
     the questions, full width, collapsed by default (only its header bar with the toggle is visible), and
     when open it has max-height 50vh with its own scroll. Resizer hidden when stacked.
   - Panel content: `periodic-table` → `periodicTable()` (below); `text` → `richText(ref.content, 'div',
     'ref-text')` then `renderMath`; `image` → `img` with `src = safeImageUrl(url)`, `alt`, `loading=lazy`,
     max-width 100%, and a "Open full size" link (`target=_blank rel=noopener noreferrer`).
   - Answers/progress are never touched by the pane: it is a sibling of the questions, so rerenders of the
     stage must not rebuild it (build it once in `render()`), and toggling/resizing must not re-mount cards.
3. **Periodic table** (`js/lib/elements.js`): `export const ELEMENTS = [{ number, symbol, name, mass, group, period, category }]`
   for all 118 elements (mass: standard atomic weight to 2–4 significant decimals as commonly printed, e.g.
   H 1.008, C 12.011, Cl 35.45, Fe 55.845; for elements with no stable isotope use the conventional mass number
   in brackets as a string like "[98]" for Tc), `group` 1–18 (lanthanides/actinides: `group: null`,
   `period: 6|7`, category 'lanthanide'|'actinide'), category one of: alkali-metal, alkaline-earth-metal,
   transition-metal, post-transition-metal, metalloid, nonmetal, halogen, noble-gas, lanthanide, actinide.
   `periodicTable()` (in reference-pane.js) renders an accessible 18-column CSS grid (`table`-like semantics:
   use a real `<table>` with `<caption>` "Periodic table of the elements", or a grid with `role="grid"`; your
   choice, but each cell must be readable by screen readers as e.g. "26 Fe, Iron, 55.845"). Each cell shows
   atomic number, symbol (large), atomic mass (monospace). Lanthanides/actinides in two rows below. Category
   is shown by a subtle background **and** a legend; never needed to read the table. Clicking/Enter on a cell
   shows a detail line under the table (`data-testid="pt-detail"`) with name, number, mass, group, period.
   The table must fit the pane: allow horizontal scroll inside the pane at narrow widths; cell testids
   `pt-<Symbol>` (e.g. `pt-Fe`).
