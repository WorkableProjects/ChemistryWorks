## Types
- **multipart** (group Basics, short "Multi-part"): `{ stem?: text, parts: [ question, … ] }` where each part is a full
  question object of any **auto-graded** type (not short/open/orbital/multipart/manual), ids unique within the question
  (`a`, `b`, …), labelled (a) (b) (c). Normalize/validate each part with `H.normalizeQuestion` / `H.validateQuestion(part,
  `${where} part (a)`, errors)`. Answer `{ partId: partAnswer }`. Score = Σ part points earned / Σ part points
  (`H.gradeQuestion(part, answer[part.id])`); `full` only when every part is fully right; question `points` = sum of part
  points (normalize sets it; validate warns if they differ). Widget: stem then each part's widget built with
  `buildWidget` from `js/views/runner/widgets.js` (import it; the import cycle is safe because it is only called at
  render time) with a sub-api that reads/writes `answer[part.id]`. Editor: list of parts with add (type picker limited to
  auto types) / remove / reorder, each part edited with `typeEditor` from `js/views/admin/editors/core.js`. Answer/key
  text: "(a) …; (b) …".
- **naming** (group Chemistry, short "Naming"): `{ direction: 'toName'|'toFormula', prompt: 'CuSO4·5H2O' | 'copper(II) sulfate',
  answers: [accepted…] }`. toName: normalize case, spaces, hyphens, "mono" prefix on the first element optional,
  Roman numerals vs "(II)" spacing ("copper (II)" = "copper(II)"), "ic/ous" not auto-converted; accept any listed answer.
  toFormula: reuse `formulasEqual` from `js/lib/formula.js`. Widget: prompt shown (formula via `formulaToHTML`) +
  text input (formula input shows the same live preview as the formula widget).
- **dropdown** (group Match & sort, short "Dropdown cloze"): text with markers like fill-in-the-blanks
  (`js/lib/blanks.js` `splitBlanks` / `markerIds` style `[[b1]]`), `blanks: [{ id, options: [..], answer }]`; per-blank
  credit (`partialCredit` default true). Native `<select>`s inline (keyboard + screen reader friendly), each labelled
  "Blank 1 of 3".

## Per-question extras (any type; all optional, off by default)
- `confidence: true` → after answering, a 3-step "How sure are you?" (Guessing / Fairly sure / Certain) row on the card;
  stored with the answer in a separate field: answers keep their shape; save confidence in the runner state under
  `confidence: { [qid]: 1|2|3 }` and include it in the submission payload (find where `buildPayload` in
  `js/lib/submit.js` collects data — read-only for you: if it needs a change, report it; you may pass it through an
  existing generic field if one exists). Show it in results and as a column in Insights (average confidence per question,
  and "confident but wrong" count).
- `hint: { text, cost }` (cost = points deducted, ≤ question points) → "Show hint (−N pt)" button; once revealed it stays
  revealed (persist like answers), and `gradeQuestion` subtracts the cost from points earned (never below 0). Grading
  must know it was revealed: pass a `hintsUsed` set into `gradeTest(test, answers, { hintsUsed })` (add the optional
  third parameter; default none) and keep the old two-argument calls working.
- `explanation`: already a common field; make sure every type (including the new ones) shows it in results/feedback after
  release.
- Builder: a "Extras" disclosure in the common question settings with the confidence switch and hint text + cost.
