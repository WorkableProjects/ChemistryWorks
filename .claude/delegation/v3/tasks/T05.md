# T05 — Runner/results animations + polish pass (V3-06 rest, V3-07)

Read docs/v2.5/v3.0plan.md "V3-06" and "V3-07", docs/DESIGN.md, and .claude/delegation/v3/reports/T03.md (motion tokens,
`prefersReducedMotion`, `countUp`, `stagger`, `viewTransition` already exist in js/lib/theme.js / js/ui.js — use them).

## Goals
1. Runner (js/views/runner.js, css/runner.css): in focus mode, question card slides in from the direction of travel (next →
   from right, previous → from left; opacity+transform, --dur-base); progress bar width transitions smoothly; navigator chip
   briefly pops (scale) when a question becomes answered or flagged; small "Saved" tick appears briefly on autosave
   (find the autosave/saveTimer code); timer gets a warning color for the final 60 s (existing pulse covers final seconds —
   keep it). No other motion while answering. All disabled by reduced motion (tokens already go to 0).
2. Results (js/views/results.js) and css: score counts up from 0 (`countUp`), a percent ring (SVG circle stroke-dashoffset)
   draws in, question rows stagger in (`stagger`), confetti only when percent ≥ test.passingPercent (or ≥ 90 when
   passingPercent is null) — find the existing confetti (`results-fall`).
3. Accessibility: aria-live="polite" for the runner timer's minute announcements (not every second), results score, labels
   (aria-label) on icon-only buttons in runner/results/feedback/admin header, touch targets ≥ 44px for runner controls
   (CSS min-height/min-width). Keep existing data-testids.
4. Performance: in js/app.js lazy-load the rarely needed heavy views with dynamic import(): `admin`, `game`, `mode-select`.
   Keep the VIEWS map contract: make navigate() able to await a loader (e.g. VIEWS entries may be `() => import(...)`) while
   keeping other views synchronous. Preserve the existing view-transition / navSeq race-guard logic in navigate() exactly.
   KaTeX: if index.html loads KaTeX unconditionally, change it to load on demand only when renderMath() finds `$` / `\(`
   in the DOM (find renderMath in js/ui.js; there is a waitForKatex in js/views/admin/export-view.js that must keep working —
   it polls for window.katex + window.renderMathInElement).
5. Error/empty states: ensure the landing "test not found" and runner offline/outbox notices use the `.notice` style with a
   Retry where a retry makes sense. Copy: plain language, consistent words "submit", "release", "test".
