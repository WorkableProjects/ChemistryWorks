# T03 — Motion tokens, reduce-motion switch, global UI animations (V3-06 part 1)

Read docs/v2.5/v3.0plan.md section "V3-06" and docs/DESIGN.md first. Static ES-module app, no build, no deps.

## Goal
1. css/base.css: motion tokens on :root — `--dur-fast:120ms; --dur-base:240ms; --dur-slow:400ms;
   --ease-out:cubic-bezier(.2,.8,.2,1); --ease-spring:cubic-bezier(.34,1.56,.64,1)`. Replace hard-coded durations in
   base.css/admin.css/references.css with tokens where obvious. Under `prefers-reduced-motion: reduce` and under
   `:root[data-motion="reduce"]`, set all durations to 0ms and disable animations/transitions globally
   (`*, *::before, *::after { animation-duration: 0.01ms !important; animation-iteration-count:1 !important; transition-duration:0.01ms !important; }`).
   Also `::view-transition-*` animations off under reduce.
2. Manual "Reduce motion" switch next to the theme control. Find the theme control (js/lib/theme.js and where it is rendered
   in js/ui.js appHeader or similar). Persist in localStorage key `reduceMotion` ('1'/'0') via js/lib/storage.js; apply as
   `document.documentElement.dataset.motion = 'reduce'` on load (call from theme.js init path that already runs at startup).
   Export `prefersReducedMotion()` from js/lib/theme.js (true if OS setting or app switch) for JS-driven animations.
3. js/ui.js: export `viewTransition(fn)` — calls `document.startViewTransition(fn)` when supported and motion is not
   reduced, else calls fn() directly. (Opus will wire it into app.js navigate(); do not edit app.js.)
   Toast slide-in animation (find toast() in ui.js + its CSS). Export `countUp(el, to, { duration=600, decimals=0, suffix='' })`
   (requestAnimationFrame; instant when reduced motion) and `stagger(listEl, { step=40 })` that sets
   `style.animationDelay` on children with class `stagger-item` (CSS keyframe `rise` already exists in base.css — check).
4. js/views/landing.js: sign-in card rises in; code input shakes on invalid code (reuse existing `.shake` class, see
   js/app.js adminGate for the pattern); "resume" / submitted-tests lists appear staggered.
5. Admin: css/admin.css drag handle lift shadow while reordering questions (find the reorder CSS classes used by builder —
   CSS only, do not edit builder.js); skeleton loaders reuse existing `adm-shimmer`.

Rules: transform/opacity only, 120–400 ms, no motion that delays input.
