## App bugs found (with proposed fixes)
No assertion failed because of an app bug. Two low-severity focus races in the app cause intermittent mis-typed input, only when input arrives within about 100 ms of a view rendering (not a realistic human case). I worked around both in the tests by waiting for the focus to settle.
1. `js/views/landing.js` line 129-130: `setTimeout(() => focusEl?.focus(), 60)` runs after render. If a user or automation focuses another field in that window, the text goes into the wrong input. I saw `demo-email` text land in `demo-name` in about 10% of mobile runs.
   - Related: when the admin gate is open, `js/app.js` `adminGate()` calls `navigate('landing')` and then `input.focus()` at 50 ms. The landing view's 60 ms timer then moves focus to `demo-name`, behind the modal, so the admin code field loses focus.
   - Proposed fix: skip the landing autofocus when `#modal-root .modal-overlay.is-open` exists, or only focus if `document.activeElement` is `body`. Alternatively use `autofocus` and drop the timer.
2. `js/views/admin/builder.js` `addQuestion` (line ~410): focuses `q-text` 80 ms after adding. Typing into another field of the new editor within that window goes into `q-text`. Proposed fix: only focus if `document.activeElement` is `body` or the add-menu button.
