## Deviations from the spec
- Prev/Next/Review buttons are rendered ONCE in a row under the card (not inside each card) so `prev-btn`/`next-btn`/`review-btn` testids are unique. In focus mode only the active card is in the DOM at rest (the outgoing card is kept ~320ms for the slide), so `option-<id>`, `numeric-input`, etc. are also unique in focus mode. In scroll mode all cards exist, so option/flag/etc. testids repeat; tests should scope with `[data-testid=question-card].is-active` or `[data-question-id=...]`.
- In preview mode the results page has a single `home-btn` whose label is "Back to builder" and navigates to admin (instead of two buttons).
- Extra testids not in the architecture list: `timeup-modal`, `shortcuts-btn`, `navigator-submit`, `filter-all|incorrect|correct`.
- Drawer on desktop is a floating panel that does not cover the footer; main content shifts left 150px at >=1100px while it is open. On <=720px it is a full-height overlay drawer that closes on tile click.
- Option arrow keys: Up/Down move within a group (and select in mcq); Left/Right stay mapped to prev/next question.
- `5 minutes left` / `1 minute left` toasts are skipped if that threshold was already passed when the runner rendered.
- The time-up modal opens on top of the results page after submission and must be dismissed (Escape or "See my results") before the page is clickable.

## Notes for later tasks
- buildPayload is called with `flags: { tabSwitches, autoSubmitted, mode }` (camelCase, as the task spec says). It correctly produced `tab_switches/auto_submitted/mode` in the stored payload in my run.
- A page reload counts as one tab switch (visibilitychange -> hidden fires on unload). Harmless, but E2E tests asserting `tab_switches === 0` after a reload would fail.
- Progress is saved on every change (text inputs debounced 250ms) and once on first render, so a student who opens a test and does nothing appears in the landing "resume" list with 0 answered.
- Numeric preview empty-state text is "Scientific notation works: 6.02e23 or 6.02 × 10^23"; unparseable shows exactly "Not a number yet".

- Review items: non-correct items start expanded, correct ones collapsed (`data-correct`, plus `data-status`).
