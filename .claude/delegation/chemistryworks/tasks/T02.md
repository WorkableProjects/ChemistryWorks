## Runner requirements (`render(root, ctx, { test, source, preview })`)
1. **Layout:** `appHeader` (subtitle = test title) with right side: timer pill (`timer`), mode toggle (`mode-toggle`, only if `test.allowModeToggle`), navigator toggle (`navigator-toggle`), `userBadge(ctx.user)` (no sign-out button during a test). Directly below the header, a full-width thin progress bar (`progress-bar`, role=progressbar, aria-valuenow = answered count, aria-valuemax = total) whose fill animates width continuously (`transition: width 400ms var(--ease)`), plus `progress-text` ("3 of 7 answered"). In preview mode show a sticky banner (`preview-banner`) "Preview mode — answers are not submitted" with `exit-preview` button → `ctx.navigate('admin')`.
2. **Question order:** if `shuffleQuestions`, `seededShuffle(questions, email + code)`; if `shuffleOptions`, shuffle each mcq/multi question's options with seed `email + code + qid`. Order must be stable across reloads.
3. **Modes:** `focus` (default from `test.defaultMode || ctx.config.DEFAULT_MODE`) shows one question card at a time: cards slide horizontally (`transform: translateX()`, `transition: transform 280ms cubic-bezier(0.4,0,0.2,1), opacity 280ms`), direction-aware (next slides left, prev slides right), no layout shift (fixed-position track / grid stacking). The current card has class `is-active`. `scroll` mode renders all cards stacked; an IntersectionObserver updates the "current" question as the user scrolls; navigator clicks smooth-scroll. Switching mode preserves answers and current question.
4. **Question card** (`question-card`, `data-question-id`): "Question N of M", type pill (TYPE_LABELS), points ("2 pts"), flag button (`flag-btn`, aria-pressed, amber when flagged), question text via `richText` + `renderMath`, the answer widget, `clear-answer` link (only when answered), and in focus mode Prev/Next buttons (`prev-btn`/`next-btn`; on the last question Next becomes "Review & submit" → opens submit modal; also a `review-btn` that opens the navigator/review panel).
5. **Widgets** (all update the answers map, autosave, update progress/navigator instantly):
   - mcq: radiogroup of option cards (`option-<id>`, role=radio, aria-checked) with a letter badge A, B, C…; click selects; arrow keys move within group. Selection: border → `--primary`, `transform: scale(1.01)`, soft glow `box-shadow: 0 0 0 4px var(--primary-ring)`, a check icon pops in (spring easing). Hover lifts subtly.
   - multi: same cards as checkboxes (role=checkbox, aria-checked), hint "Select all that apply".
   - numeric: `numeric-input` (inputmode=decimal) with unit suffix chip if `unit`; `numeric-preview` shows "Interpreted as 1.204 × 10²⁴" (use parseNumber; scientific display with superscript for |x|≥1e5 or <1e-3; shows "Not a number yet" in muted danger when unparseable and non-empty). Debounce saving 250ms but update preview live.
   - formula: `formula-input` (spellcheck off, autocapitalize off) with `formula-preview` showing `formulaToHTML(value)` inside `<span class="formula">` (the only allowed innerHTML). Hint: "Type H2O, CuSO4.5H2O, SO4^2-".
   - truefalse: two large side-by-side buttons `tf-true` / `tf-false` (role=radio) with check/x icons.
   - matching: a **matrix** (table): rows = left items, columns = right items, each cell a radio input (`match-<leftId>-<rightId>`, name per row) styled as a circular target; row/column headers are rich text. On narrow screens (<600px) the table scrolls horizontally inside its card with sticky first column. Selecting fills the dot with a spring animation.
6. **Navigator panel** (`navigator`): slide-in drawer (from right, 280ms) listing numbered tiles `nav-item-<qid>` with classes `is-answered`, `is-flagged`, `is-current`; legend; counts of answered/flagged/unanswered; "Submit test" button (`submit-btn`). Clicking a tile jumps to the question (focus mode: slides; scroll: scrolls) and closes the drawer on mobile. A persistent `submit-btn` must also exist somewhere visible in the runner footer/header at all times so tests can always click it (only one element may have the `submit-btn` testid in the DOM at a time — put it in the sticky footer bar, and give the drawer's button a different testid `navigator-submit`).
7. **Keyboard shortcuts** (ignored while focus is in a text input/select, except Enter in inputs moves next): ←/→ prev/next (focus mode), `1`–`9` or `A`–`Z` select option N in mcq/multi (toggle for multi) for the current question, `T`/`F` for truefalse, `G` toggles flag (not F, which is "false"), `N` opens navigator, `?` opens `shortcuts-modal`. Show a small "Keyboard shortcuts (?)" hint button in the footer.
8. **Autosave/resume** (skip entirely in preview): key `progress:<email>:<CODE>`, shape in ARCHITECTURE.md; save on every change; on render, if saved progress exists restore answers/flags/index/mode/startedAt/tabSwitches and toast "Welcome back — your answers were restored". `startedAt` set at first render if not restored.
9. **Timer:** if `timeLimitMinutes`, countdown computed from `startedAt` (so reload doesn't reset): `formatDuration(remaining)`; pill turns warning at ≤5 min (toast once "5 minutes left"), danger + pulse at ≤1 min (toast once); at 0 auto-submit with `flags.auto_submitted = true` and a modal "Time's up — your test was submitted". Untimed: show elapsed time counting up. Use one `setInterval(…, 1000)` cleared in cleanup.
10. **Integrity:** count `visibilitychange` → hidden events as tabSwitches (non-preview), persist them; no blocking UI.
11. **Submit flow:** `submit-btn` opens `openModal` with testid `submit-modal`: summary (answered X of Y, flagged count, time used), and if unanswered > 0 a warning block `unanswered-warning` listing the unanswered question numbers as buttons that jump to them (and close the modal). Actions: `cancel-submit` ("Keep working") and `confirm-submit` ("Submit test", primary). On confirm: disable, show spinner, `grade = gradeTest(test, answers)`; if preview → `ctx.navigate('results', { test, grade, payload: null, submission: null, preview: true })`; else `payload = buildPayload({ test, grade, user: ctx.user, startedAt, submittedAt: Date.now(), flags: { tabSwitches, autoSubmitted, mode } })`, `submission = await submitResults(payload, { config: ctx.config })`, remove progress key, navigate to results. Guard against double submission (timer + click race).
12. **Cleanup** returned from render: clear interval, remove keydown/visibilitychange listeners, disconnect observers, close drawer.
13. If `ctx.user` is null and not preview → `ctx.navigate('landing', { code: test.code })`. In preview with no user, use `{ name: 'Preview', email: 'preview@local' }` for display only.

## Results requirements (`render(root, ctx, { test, grade, payload, submission, preview })`)
1. Header (appHeader with home click → landing). Main: a celebratory but professional card.
2. Always show the **Instant Submission confirmation**: completion time (`completion-time`, from payload.duration_seconds via formatDurationLong; in preview compute "—"), answered count (`answered-count`, "6 of 7 answered"), and submission status (`submission-status` with attrs `data-gas`, `data-netlify`, `data-queued`): human chips "Saved to Google Sheet ✓" / "Not configured" / "Failed", "Netlify backup ✓"/…; if `queued`, a warning notice "We couldn't reach the server. Your submission is saved on this device and will retry automatically." + `retry-submit` button calling `flushOutbox({ config: ctx.config })` then toast result. In preview show a notice "Preview — nothing was submitted".
3. If `test.showResults` (or preview): animated score ring (SVG circle stroke-dashoffset animating 0 → percentage over ~1.1s, number counting up with requestAnimationFrame; final text exactly `${grade.percentage}%` in `score-percentage`), `score-points` "`${scoreAchieved} / ${scoreTotal}`", `score-correct` "`${correctCount} of ${questionCount} correct`". If `passingPercent` set, `pass-badge` "Passed" (success) or "Not yet" (warning). Ring color: success ≥ 80, primary ≥ 50, warning below. A tasteful CSS confetti burst for ≥ 90% (skip under reduced motion).
   Else show `results-hidden`: "Your responses have been recorded. Your teacher will share results."
4. If `test.showCorrectAnswers && (test.showResults || preview)`: `review-list` of expandable items `review-item-<qid>` (data-correct) showing number, rich question text, status icon (correct/partial/incorrect/unanswered with points earned/possible), "Your answer" (givenAnswerText; render formula answers via formulaToHTML), "Correct answer" (correctAnswerText), explanation (rich). Items animate in with a short stagger. Filter chips: All / Incorrect / Flagged? (All / Incorrect / Correct is enough).
5. Buttons: `home-btn` "Back to home" → `ctx.navigate('landing')`; in preview, "Back to builder" → `ctx.navigate('admin')`.
6. Call `renderMath(root)` after mounting.

## CSS requirements (css/runner.css)

Prefix classes with `runner-`, `q-`, `opt-`, `nav-`, `results-` to avoid collisions with admin.css.
