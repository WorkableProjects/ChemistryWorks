## Steps
1. **Question bank** — add 3 tests, chemistry must be accurate (double-check every key and calculation; use standard atomic masses H 1.008, C 12.01, N 14.01, O 16.00, Na 22.99, Cl 35.45, S 32.07, Ca 40.08):
   - `CHEM102` "Stoichiometry & the Mole" (10 questions; timeLimitMinutes 30; passingPercent 70)
   - `CHEM110` "Periodic Table & Bonding" (10 questions; shuffleOptions true)
   - `CHEM201` "Acids, Bases & Equilibrium" (10 questions; showCorrectAnswers true; passingPercent 75)
   Each must use all six question types at least once, include KaTeX/mhchem notation in some text (`$\\ce{...}$`), explanations on every question, sensible tolerances for numeric answers. Add them to `data/tests/index.json`.
2. `scripts/validate-tests.mjs`: for each `data/tests/*.json` except index.json → normalizeTest + validateTest; file name must equal `<code>.json`; every index.json entry must have a file and vice versa; print a summary table; exit 1 on any error.
3. `test/unit/bank.test.mjs`: every bundled test validates; answering every question with its own key (numeric: `String(correctAnswer)`, formula: first accepted) grades to `"100.00"`; question ids unique; `npm run validate:tests` logic reused or spawned.
4. `test/unit/stats.test.mjs`: unit tests for the admin's pure stats helpers (see note above): mean/median (odd/even/empty), histogram bucket edges (0, 9.99, 10, 100), per-question aggregation, CSV quoting (commas, quotes, newlines).
5. **E2E suite** in `test/e2e/` using `node:test` + `import { chromium } from 'playwright'` (pre-installed; do NOT npm install). Create `test/e2e/helpers.mjs`: start server via `listen(0)`, launch chromium once per file, `newContext()` per test; `page.addInitScript` to set `window.CHEMISTRYWORKS_CONFIG = { GAS_WEB_APP_URL: 'https://gas.example.test/exec', NETLIFY_FORMS: true, ...overrides }`; `context.route` to (a) capture GAS POSTs (store parsed JSON bodies) and fulfill 200, (b) capture Netlify `POST /` bodies (parse form-urlencoded), (c) abort/fulfill-empty all other non-localhost requests (fonts, KaTeX CDN, GIS) so tests are deterministic and offline-safe; collect `pageerror` and console errors and fail the test if any occur (ignore resource-load errors from aborted CDN requests); helper `signIn(page, name, email)` via demo form; helper to serve ad-hoc test JSON by routing `**/data/tests/<CODE>.json`.
   Required scenarios (separate files by area, e.g. `landing.test.mjs`, `runner.test.mjs`, `results.test.mjs`, `admin.test.mjs`, `resilience.test.mjs`):
   - Landing: unauthenticated shows sign-in; demo validation error for bad email; sign in → code card + user badge; unknown code → `code-error`; valid code opens runner; `?code=CHEM101` unauthenticated → card title contains CHEM101 → after sign-in runner opens directly; sign out returns to sign-in.
   - Full correct run of CHEM101 in focus mode (using every widget) → `score-percentage` = `100.00%`, `score-points` = `12 / 12`; captured GAS payload has all Payload fields with correct student name/email/test_code/score and 7 responses; captured Netlify body contains every hidden-form field name.
   - Mixed answers with partial credit on matching and multi → exact expected percentage (compute by hand in the test and assert the string).
   - Progress bar aria-valuenow increments; navigator tiles reflect answered/flagged/current; unanswered warning lists missing questions in the submit modal and its buttons jump to them; cancel keeps working.
   - Keyboard: `→`/`←` navigate, `2` selects 2nd option, `t` sets true, `g` flags, `?` opens shortcuts modal.
   - Scroll mode toggle shows all cards and answers persist across the toggle.
   - Autosave/resume: answer 3 questions, reload page → answers restored and toast shown; landing shows `resume-CHEM101`.
   - Timer: ad-hoc test with `timeLimitMinutes: 0.05` auto-submits and results show; payload `flags.auto_submitted === true`.
   - `showResults: false` → `results-hidden` visible and no `score-percentage`.
   - Resilience: GAS route aborted and Netlify returns 500 → results show queued warning (`submission-status` data-queued="true"); then make routes succeed and click `retry-submit` → toast + GAS capture received the same submission_id.
   - XSS: ad-hoc test whose question/option text is `<img src=x onerror="window.__xss=1">` → rendered as literal text, `window.__xss` undefined.
   - Formula widget preview: typing `CuSO4.5H2O` shows `<sub>` in `formula-preview`; numeric preview for `6.02x10^23`.
   - Mobile (viewport 375×740): runner and results have no horizontal page scroll (`document.documentElement.scrollWidth <= innerWidth`).
   - Admin: `?admin=true` gate rejects wrong code, accepts `chemadmin`; library lists CHEM101 and the new bank tests; builder: new test, set code/title, add an mcq and a numeric question via `add-question-<type>`, fill fields, `validation-errors` data-count reaches 0, `save-draft`, `preview-test` → runner preview with `preview-banner`, complete and submit → results without any GAS/Netlify capture; JSON mode edit + `apply-json` updates title; invalid JSON shows an error; analytics with source `device` after a real student submission in the same context shows `kpi-submissions` = 1 and the row in `results-table`; `export-csv` triggers a download (use `page.waitForEvent('download')`).
   Keep each test independent (fresh context), use web-first waiting (`locator.waitFor`, `expect`-style polling via small helpers) — never fixed sleeps longer than needed except for the timer test. Whole suite should finish in < 3 minutes.
6. Run `npm test` and `npm run test:e2e`; all must pass. If an E2E failure is caused by a real app bug outside your owned files, do NOT edit app code: keep the test (it's correct), mark it in the report with the exact failing assertion, the file/line you believe is wrong, and a proposed fix. Never weaken assertions to get green.

## Acceptance criteria
- `npm run validate:tests` exits 0
- `npm test` exits 0
- `npm run test:e2e` exits 0, or every failure is documented as an app bug with a proposed fix
- `git status` shows changes only in owned paths
