## Root causes
1. Questions drawer: #app has class view-enter (css/base.css, animation view-in ... both). Fill-mode "both" keeps `transform: none` applied forever, which makes #app the containing block of position:fixed descendants, so .nav-host (fixed) was laid out relative to the page and scrolled away (measured drawer top -2920 at scrollY 3000). Fix in css/runner.css: `body[data-view="runner"] #app.view-enter { animation-fill-mode: backwards; }` (base.css not owned). Verified at 1280 and 390 widths; e2e test fails without the fix, passes with it.
2. Ordering:
   - Student view: item text was squeezed between number, handle and arrows on phones; rows re-ran the entry animation on every move (flash); HTML5 drag never works on touch. Fixed: text gets its own full-width row at <=520px, animation only on first paint, handle enlarged and supports pointer (touch/pen) dragging, overflow-wrap on text.
   - Admin builder ordering editor: 5 children (number, text, up, down, remove) were put in the 2-column `.adm-opt--plain` grid, wrapping over several lines. New `.adm-opt--order` 5-column grid (css/admin.css).
   - Note: question/item text is invisible (.rich opacity 0) until KaTeX loads or a 1.2s fallback; offline in e2e this looks blank in early screenshots. Not changed.
3. Image choices: schema (optional `image {url, alt}` on mcq/multi options, matching left/right, ordering items; normalized only with url; validated with safeImageUrl + alt; text OR image required), runner rendering (lazy, alt, max-height 140px, object-fit contain; matching headers and ordering rows too), builder "Add image" toggle with URL + alt (+preview) per option/item, results review and export view show the chosen/correct pictures, formatAnswer/optionText falls back to "[image: alt]" for image-only choices (matching left too). Grading unchanged (by id). True/false skipped.
