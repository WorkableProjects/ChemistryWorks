## Game design (original)
- One question at a time, auto-gradable types only: use `gradeQuestion(q, answer)` from js/lib/grading.js (returns points/correctness — read it). Skip question types that need manual grading (open-ended, and any where gradeQuestion says needsGrading) and student-drawn types (lewis, structure, orbital) — show "N questions skipped in game mode" if any.
- Supported inputs in game: mcq (big colored answer tiles with shapes/numbers, keyboard 1-4), multi (tiles + Submit), truefalse (two tiles), numeric/short/formula (text input + Submit). For other auto-gradable types, skip.
- Per-question countdown (e.g. 20s, ring/bar), points = base 1000 × speed factor (min 500 when correct), streak multiplier (streak ≥3 → +10% per extra, cap), 0 for wrong/timeout. Instant feedback card (correct/incorrect, correct answer via formatAnswer, points gained, streak), then Next.
- Power-up flavor (original): e.g. one "50/50" per game for mcq, one "Freeze time" +10s. Keep small.
- End screen: total score, accuracy, best streak, per-question review list, local personal best per test (localStorage via js/lib/storage.js `load/save`), buttons: Play again (reshuffle via seededShuffle with new seed), Switch to Study mode, Home.
- Respect prefers-reduced-motion (js/ui.js prefersReducedMotion). Accessible: aria-live for feedback, buttons are real buttons, focus management. Render math with renderMath(root) after mounting, and question images via js/views/question-image.js if present.
