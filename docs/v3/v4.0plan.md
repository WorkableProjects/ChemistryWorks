## What the code does today (research)

- **Logos are in, the UI isn't.** `assets/brand/` has `mark`, `wordmark` (+ `-dark`) PNGs, a favicon, a touch icon and source SVGs (`assets/brand/source/`). `brandLogo()` in `js/ui.js` places them in the header and on the landing page. Everything else still uses the v2 "Lab notebook" theme (`docs/DESIGN.md`): warm paper, ink-blue `#2348A4` accent, graph-paper texture.
- **Brand colors don't match the theme.** Sampled from the logo: navy `#00224F`, teal `#01A9AE` (dark variant: `#E7EDF7` / `#2CC5C9`). The app accent is a different blue, and the warm paper fights the cool navy/teal.
- **Teal fails contrast as text.** `#01A9AE` on white is about 2.9:1 (below 4.5:1 for text and 3:1 for UI edges). Teal can be a fill or decoration; text and control edges need a darker teal (around `#00797D`, about 5.2:1).
- **Product name is mixed.** The logo says "ChemWorks"; titles, PDF export, CSV filenames, docs and `package.json` say "ChemistryWorks".
- **Question types:** 20 (`TYPE_LABELS` in `js/lib/schema.js`). v3 split per-type code into `js/lib/qtypes/`, `js/views/widgets/` and `js/views/admin/editors/`, so a new type is now mostly new files plus registry entries. `runner.js` (1,214 lines) and `builder.js` (1,489 lines) are still large.
- **Teacher tools:** library, visual builder, grading (filters, release all, allow retake, overrides, comments, gradebook CSV), PDF export, settings. No per-question analytics, no shared question bank, no open/close dates, no per-student accommodations, no grade-by-question view.
- **Games:** Classic, Survival, Lightning Round, Element Hunt, Match-Up, Flashcards (`js/lib/games/`, `js/views/games/`, shared `game-shell.js`). Test JSON has `gameMode` and optional `games: [...]`. Game rules (time, lives, length, power-ups) are hard-coded per game. Best scores are per device.
- **Backend:** `apps-script/Code.gs` 3.0.0, 24 Submissions columns, public `getTest` / `getStudentStatus` / `submit`, admin actions for tests and grading.

## V4-00 — Brand + design system

**Goal:** one look, built from the logo, used everywhere. Replace "Lab notebook" with a cleaner, cooler system ("ChemWorks Lab").

**Name**
- **ChemistryWorks** is the full name; **ChemWorks** is the short name (the logo).
- Full name: `<title>`, landing intro text, PDF export footer, docs, `package.json`, sign-in prompts.
- Short name: the wordmark, the compact header, the home-screen app name (`apple-mobile-web-app-title`), toasts where space is tight.
- Never mix them in one sentence. Keep the storage prefix (`cw:`) and backend names unchanged.

**Logo use**
- Switch `brandLogo()` to inline SVG from `assets/brand/source/` (sharp at any size, recolorable through `currentColor` / CSS variables). Keep PNGs for favicon, touch icon, PDF and social preview.
- Clean up the source SVGs (they are export output with filters and clip paths): one simple path set per mark, `viewBox` trimmed, colors as `fill="var(--brand-navy)"` / `var(--brand-teal)`.
- Variants: full wordmark, mark only, mono (one color, for print and high contrast), and the animated flask loader (from v3) as the one app-wide loading indicator.
- Placement rules: wordmark on landing and admin sign-in; mark + "ChemWorks" in the app header; mark only under 480 px; never stretched, minimum clear space = the flask's bubble diameter.

**Tokens (`css/base.css`)**

| Token | Light | Dark | Notes |
|---|---|---|---|
| `--brand-navy` | `#00224F` | `#E7EDF7` | Headings, header, primary button fill (light) |
| `--brand-teal` | `#01A9AE` | `#2CC5C9` | Fills, highlights, progress, game accents. Never body text on light surfaces |
| `--brand-teal-ink` | `#00797D` | `#2CC5C9` | Teal text, links, control edges (≥ 4.5:1) |
| `--bg` | cool off-white (around `#F5F8FB`) | deep navy (around `#0B1424`) | Replaces warm paper |
| `--bg-elev` / `--bg-sunken` | white / pale blue-grey | lifted navy / darker navy | Solid surfaces |
| `--primary` | navy | teal | Buttons, focus ring; derived `-hover`, `-soft`, `-ring` |
| `--success` / `--danger` / `--warning` | re-tuned for cool surfaces | same | Keep icon + text pairing |

- Surfaces: cool off-white in light mode and deep navy in dark mode (chosen to match the logo; warm paper is dropped).
- Texture: drop graph paper. Optional subtle hex/molecule pattern on the landing hero only (decorative SVG, off under `prefers-contrast: more`).
- Type: keep Atkinson Hyperlegible (body) and IBM Plex Mono (formulas, numbers). Add a geometric display face close to the wordmark for headings, buttons and scores (shortlist: Plus Jakarta Sans, Outfit, Lexend 600–800; pick the closest match to the wordmark's round "C", "W" and "k" in a side-by-side, Google Fonts only).
- Accent palettes (`data-accent`): keep the switch, but default student and admin both to navy/teal; admin gets a darker header bar instead of violet.
- Rewrite `docs/DESIGN.md` for the new system. Extend `v2-contrast.test.mjs` to cover every new token pair in both themes.

**Acceptance criteria**
- [ ] Full name and short name used per the rules above; no mixed use in one string.
- [ ] All text tokens ≥ 4.5:1 and control edges ≥ 3:1 on all surfaces, light and dark (unit test).
- [ ] Logo is crisp at every size, correct in dark mode and high-contrast mode, and never distorted.
- [ ] No hex literals in view CSS (lint check in tests).

## V4-01 — Full UI revamp

Apply V4-00 view by view. Same features, same `data-testid`s (E2E tests must keep passing), new layout and components.

**Shared components (`js/ui.js` + `css/base.css`)**
- App shell: slim navy header with logo, test title, theme/motion/accent menu in one settings popover.
- Buttons: one size scale (sm/md/lg), icon + label, 44 px minimum touch target.
- Cards, pills, tabs, modals, toasts, empty states, skeleton loaders: restyled once, used everywhere.
- One icon set (inline SVG sprite, e.g. Lucide-style strokes) replacing mixed glyphs/emoji.

**Student views**
- **Landing:** hero with the wordmark, code entry as the main action, sign-in card, "Continue where you left off" and "Your tests" (with Released / Submitted / In progress badges) as cards.
- **Mode select:** three large cards (Take test, Study, Play) with icons and one-line descriptions.
- **Runner:** calmer, more space. Sticky top bar (title, timer, progress), question navigator as a collapsible side rail on desktop and a bottom sheet on phones, reference pane as a right drawer. Question card on a solid surface; no decoration during a test.
- **Results / feedback:** score ring in teal, summary chips (correct / partial / incorrect / pending), per-question cards matching the PDF.
- **Submitted / already submitted / pending:** one shared status page layout with the flask illustration.

**Teacher views**
- **Admin layout:** left sidebar (Library, Builder, Grading, Insights, Question bank, Settings) instead of top tabs; collapses to icons on narrow screens.
- **Library:** card grid or table toggle, search, filters (published, has submissions, needs grading), quick actions per test.
- **Builder:** two-pane (outline on the left, editor on the right, live student preview toggle). Question-type picker as a searchable grid with icons and short descriptions.
- **Grading:** split view (student list | submission), keyboard shortcuts (J/K next/previous, number keys for points), sticky score bar.

**PDF export:** new header with the logo, navy/teal accents in screen view, black-and-white safe in print.

**Acceptance criteria**
- [ ] Every view uses only V4-00 tokens and shared components.
- [ ] All existing E2E tests pass without changing `data-testid`s (selectors may move, IDs stay).
- [ ] Works at 360, 768, 1366 px; no horizontal scroll.
- [ ] Screenshots of every view, light and dark, attached to the PR.

## V4-02 — Teacher tools

| Tool | What it does | Backend |
|---|---|---|
| **Insights** (new admin tab) | Per test: score distribution, average, median, time spent; per question: % correct, average points, most-chosen wrong answer (for `mcq`/`multi`/`truefalse`), "flag for review" when < 40% correct. Click a question to see every student's answer. | None (computed client-side from `getResults`) |
| **Grade by question** | Grade question 5 for every student in a row, instead of student by student. Best for `short`/`open`/`orbital`. | Uses existing `saveGrade` |
| **Comment bank** | Saved reusable comments per teacher, one click to insert, optional per-question rubric (criteria + points). | Settings stored in a new `Settings` sheet (or `localStorage` first) |
| **Question bank** | Save any question to a bank shared by **all admins** on the deployment, with tags (topic, unit, difficulty, NGSS standard) and "added by". Search and insert into any test (inserting copies the question). Import from existing tests. Any admin can edit or delete; edits record who and when. | New `Bank` sheet + `listBank` / `saveBankItem` / `deleteBankItem` admin actions |
| **Question pools** | A section can draw N random questions from a pool (or from bank tags) per student. The drawn IDs are stored with the submission so grading and feedback show the right questions. | Submission stores `drawn_questions` |
| **Open / close window** | `opensAt` / `closesAt` per test. Before: "Opens on…". After: "This test is closed." Teacher can extend for one student. | `getTest` / `submit` check the window server-side |
| **Accommodations** | Per-student (by email): extra time (×1.5, ×2, custom), extra attempts, reduced answer choices for `mcq` (removes one wrong option), read-aloud on. | New `Accommodations` sheet; returned in `getStudentStatus` |
| **Duplicate / versions** | Duplicate a test with a new code; "Version B" shuffles questions and options with a fixed seed so teachers can print or assign forms. | None |
| **Regrade** | After fixing an answer key, re-run auto-grading on all submissions for that test (overrides are kept). | New `regrade` admin action |
| **Live monitor** | During a test: who has started, how far along (answered / total), time left, who has submitted, who went idle (no ping for 3 min). Auto-refreshes every 30 s while open. | Heartbeat action `progressPing` every 60 s + admin `getLive`; `Live` sheet, one row per student per test, overwritten in place (not appended) to stay within quota |
| **Gradebook export** | Keep CSV; add per-question columns option and a Google Classroom-friendly format. | None |

- Start with Insights, Grade by question and Comment bank (no backend changes), then Question bank and pools, then window/accommodations.
- Answer keys are still public (client-side grading). Pools do not change that; note it in the guide.

**Acceptance criteria**
- [ ] Insights numbers match a hand calculation on the fixture data (unit test on pure helpers in `stats.js`).
- [ ] Grade by question saves to the same rows as the per-student view.
- [ ] A pooled test shows each student only their drawn questions, everywhere (runner, results, grading, feedback, PDF).
- [ ] A closed test cannot be started or submitted, even by calling the backend directly.
- [ ] Extra time applies on any device the student signs in on.

## V4-03 — More question types

Follow the v3 per-type checklist: `js/lib/qtypes/<type>.js` (normalize, validate, grade, format), `js/views/widgets/<type>.js`, `js/views/admin/editors/<type>.js`, export rendering, `scripts/validate-tests.mjs`, a sample in `data/tests/`, a JSON example in `docs/guide.md`, unit + E2E tests.

| Type | What the student does | Grading | Priority |
|---|---|---|---|
| `multipart` — Multi-part problem | One stem (text, data table, image) with parts a, b, c… each of any auto-graded type | Sum of parts; each part graded by its own type | High |
| `naming` — Name ↔ formula | Writes the name for a formula, or the formula for a name (ionic, covalent, acids, hydrates) | Auto. Normalizes case, spacing, "mono-", Roman numerals; accepts a list of names | High |
| `dropdown` — Inline dropdown cloze | Picks words/values from dropdowns inside a sentence or equation | Auto, per blank | High |
| `dimensional` — Dimensional analysis | Builds a chain of conversion factors (fraction tiles with value + unit), units cancel visually, enters the final answer | Auto: final value (tolerance) + units; optional credit for a valid chain | High |
| `nuclear` — Isotope / nuclear notation | Fills mass number, atomic number and symbol; or completes a nuclear equation (α, β, γ) | Auto. Conservation checked | Medium |
| `reaction` — Predict the products | Types the product side (and states) of a reaction, or a net ionic equation | Auto. Reuses formula parser; order-free, coefficients optional or required | Medium |
| `vsepr` — Molecular shape | Picks electron geometry, molecular geometry and bond angle from illustrated choices | Auto, credit per field | Medium |
| `datatable` — Complete the table | Fills cells in a data table (e.g. protons/neutrons/electrons, ICE table) | Auto per cell, tolerance per column | Medium |
| `estimate` — Slider | Drags a slider to a value (pH, temperature, percent) | Auto within tolerance | Low |

- `multipart`, `naming`, `dropdown` cover the most common worksheet patterns; do them first.
- Add auto-graded types to games where they fit (`naming`, `nuclear`, `vsepr`, `dropdown` in Classic / Survival / Lightning; `naming` pairs in Match-Up and Flashcards).
- `sketch` (draw on a canvas) is **skipped** for v4: there is nowhere good to store images.

**Acceptance criteria**
- [ ] Each type can be authored in the builder and in JSON, validated, taken, auto-graded (or teacher graded), reviewed in results and feedback, exported to PDF, and used in pools/bank.
- [ ] Keyboard and screen-reader support for every new widget (no drag-only interaction).

## V4-04 — More game options

**Per-test game settings** (builder → Game mode panel, stored as `gameOptions` in test JSON):

| Option | Applies to | Default |
|---|---|---|
| Games offered | all | all playable (existing `games`) |
| Number of questions | Classic, Survival, Match-Up, Flashcards | all |
| Time per question / total time | Classic / Lightning | game default |
| Lives | Survival | 3 |
| Power-ups on/off (50/50, Freeze, + new Skip, Hint) | Classic, Survival | on |
| Untimed / relaxed mode | all timed games | off (student can turn on if teacher allows) |
| Question types included | all | all playable |
| Sound allowed | all | on (still off by default for the student) |
| Class leaderboard | all scored games | off |

**New games** (original designs only):

| Game | Mechanic | Uses |
|---|---|---|
| **Reaction Lab** | Drag coefficients and products onto a reaction bench before the timer runs out; streaks unlock harder reactions. | `balance`, `reaction`, built-in reaction list |
| **Molecule Builder** | Build a molecule from atoms to match a target formula or shape; score by speed and correctness. | Element data, `vsepr` / `structure` |
| **Tower** | Each correct answer adds a block; wrong answers make the tower wobble; three wobbles and it falls. Height = score. | All auto-graded types |
| **Mistake Review** | Replays only the questions the student got wrong (from released feedback or past game rounds) until each is right twice. Not scored. | All auto-graded types |
| **Daily Element** | One short daily challenge from built-in element data; streak counter on the landing page. | Element data |

**Progress and rewards (local only, no leaderboard):**
- XP per game, levels, and badges ("10 in a row", "Noble gas master") saved in `localStorage` per student.
- Best score per game shown on picker cards (exists), plus a personal history chart (last 10 rounds).

**Class leaderboard (only when the game option is on):**
- Shown only if the test has `gameMode: true` **and** `gameOptions.leaderboard: true`. Otherwise nothing is sent and no leaderboard appears.
- Per test and per game: top 10 best scores, plus the student's own rank. On the game picker and the end screen.
- Names: first name + last initial by default; teacher can choose "nicknames" (student picks one from a generated list like "Brave Boron", no free text) instead.
- Scores are submitted with the verified ID token; the backend keeps only the best score per student per game. Teacher can clear a test's leaderboard or hide one entry.
- Backend: `Leaderboard` sheet; public `submitGameScore` and `getLeaderboard` (verified token, checks the test's settings); admin `clearLeaderboard`.
- Cheating limit: scores are computed in the browser, so they can be faked. Cap each game's score at its maximum possible value and say in the guide that the leaderboard is for fun, not grades.
- A live team game (host-controlled, like a quiz show) is still out of scope.

**Acceptance criteria**
- [ ] Every option in `gameOptions` is respected by each game it applies to (unit tests per game).
- [ ] Untimed mode removes all time pressure, including speed points.
- [ ] With the leaderboard off, games send nothing to the backend. With it on, they send only the final score.
- [ ] A test without game mode never shows or accepts leaderboard scores (checked server-side).
