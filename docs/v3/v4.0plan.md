## What the code does today (research)

- **Logos are in, the UI isn't.** `assets/brand/` has `mark`, `wordmark` (+ `-dark`) PNGs, a favicon, a touch icon and source SVGs (`assets/brand/source/`). `brandLogo()` in `js/ui.js` places them in the header and on the landing page. Everything else still uses the v2 "Lab notebook" theme (`docs/DESIGN.md`): warm paper, ink-blue `#2348A4` accent, graph-paper texture.
- **Brand colors don't match the theme.** Sampled from the logo: navy `#00224F`, teal `#01A9AE` (dark variant: `#E7EDF7` / `#2CC5C9`). The app accent is a different blue, and the warm paper fights the cool navy/teal.
- **Teal fails contrast as text.** `#01A9AE` on white is about 2.9:1 (below 4.5:1 for text and 3:1 for UI edges). Teal can be a fill or decoration; text and control edges need a darker teal (around `#00797D`, about 5.2:1).
- **Product name is mixed.** The logo says "ChemWorks"; titles, PDF export, CSV filenames, docs and `package.json` say "ChemistryWorks".
- **Question types:** 20 (`TYPE_LABELS` in `js/lib/schema.js`). v3 split per-type code into `js/lib/qtypes/`, `js/views/widgets/` and `js/views/admin/editors/`, so a new type is now mostly new files plus registry entries. `runner.js` (1,214 lines) and `builder.js` (1,489 lines) are still large.
- **Teacher tools:** library, visual builder, grading (filters, release all, allow retake, overrides, comments, gradebook CSV), PDF export, settings. No per-question analytics, no shared question bank, no open/close dates, no per-student accommodations, no grade-by-question view.
- **Games:** Classic, Survival, Lightning Round, Element Hunt, Match-Up, Flashcards (`js/lib/games/`, `js/views/games/`, shared `game-shell.js`). Test JSON has `gameMode` and optional `games: [...]`. Game rules (time, lives, length, power-ups) are hard-coded per game. Best scores are per device.
- **Admins share one password.** Every admin action uses the single `ADMIN_KEY` script property (`js/views/admin/settings.js`, kept in `sessionStorage`), which each admin has to type in by hand. The backend can't tell teachers apart, so "added by", per-teacher comment banks and audit logs need V4-07 first.
- **Backend:** `apps-script/Code.gs` 3.0.0, 24 Submissions columns, public `getTest` / `getStudentStatus` / `submit`, admin actions for tests and grading.

## V4-FIX — Fixes before v4 work

These ship on their own, before the revamp, because teachers hit them today.

### FIX-1 — Grading "Save & next" loop (reported by Jayden) — **done** on branch `claude/fix-grading-save-loop`

- **Symptom:** after Save / Save & next, "Saved grade for …" and "That was the last one in this list." toasts kept repeating for minutes, each one throwing the teacher back to the grading list.
- **Cause:** in `js/views/admin/grading.js` the click handler was named `save()`, which hid the storage `save()` import. The line meant to remember the "Graded by" name, `save('gradedBy', …)`, called the grade-save function again with a truthy "next" flag: an endless loop of `saveGrade` requests (about 120 per second against the mock backend). It happened on **any** save with "Graded by" filled, not only on the last student; on the last one it was most visible because each loop also went back to the list.
- **Fix:** handler renamed `saveGradeAndMaybeNext()`; storage import renamed `saveLocal`. A regression E2E test checks that one click sends exactly one `saveGrade`.
- **Follow-up:** check the Submissions sheet for the affected period; repeated saves rewrote the same row (same grades), so no data should be wrong, but the Apps Script quota may have been hit that day.

### FIX-2 — Condensed question-type picker — **done** on the same branch

- The Add question menu was one column of 20 long names (taller than the screen).
- Now: four groups (Basics, Match & sort, Chemistry, Diagrams & graphs) in a two-column grid, short names ("Electron config", "Sig figs", "Lewis dots"), a small **Teacher** tag instead of "(teacher graded)", a filter box (type "lewis" → 2 results, Enter adds the first), and arrow-key navigation. Full names stay as tooltips. About 55% of the old height; still two columns on phones, scrolls inside the popup.
- Test IDs (`add-question-<type>`) are unchanged. New types from V4-03 go into a group in `TYPE_GROUPS` (`builder.js`); any type not listed lands in a "More" group automatically.
- V4-01 later adds icons and the builder's two-pane layout on top of this.

### FIX-3 — "Label the diagram" (`hotspot`) alignment + teacher editor — **done (part)**, see "Status" below

**What's wrong (from the screenshot)**
- **Pins are misaligned with the image.** The stage (`.q-hot__stage`) is `display: inline-block`, but inside a flex column (`.stack`) it stretches to the full card width. Pins are positioned in % of the **stage**, not the **image**, so whenever the image is narrower than the card, every pin is shifted right (label 3 sat in empty space past the picture). Same risk in the student runner, results, grading and PDF wherever the parent is a flex/grid column.
- **Teacher editor layout is broken.** Each label row puts a full-width text box, then the x and y number boxes (`width: 6.5em`, `type="number"`) after it; they wrap onto a second line, overflow the card on the right, and the browser's number spinner draws over the digits ("0.6X2"). Raw fractions (0.22, 0.672) mean nothing to a teacher.
- Other rough edges: a separate "Refresh picture" button, no way to drag a pin, no visible "answer circle" for the accepted distance, the selected label is only shown by colour, and the empty state is plain text.

**Fix**
- **Shared stage component** (`js/views/widgets/hotspot-stage.js`) used by the editor, runner, results, grading and PDF: a wrapper sized to the **rendered image** (`width: fit-content; max-width: 100%; align-self: flex-start`), pins and hit-testing in % of the image box, re-measured on image `load` and on resize (`ResizeObserver`). One implementation, so the teacher's view and the student's view always match.
- **Editor redesign:**
  - Image on top, full width it can take without upscaling; a label list beside it on desktop (below on phones).
  - Each label row: number badge, text box, "Placed ✓ / Not placed" status, delete. No raw x/y boxes in the default view; an "Exact position" disclosure shows x / y as **percent** (0–100) text inputs (no spinners) for keyboard users.
  - Click the image to place the selected label; **drag** pins to move them; arrow keys nudge the selected pin 1% (Shift = 5%).
  - The accepted distance is shown as a translucent circle around each pin, with a slider ("Small / Medium / Large" plus exact %), so teachers see what counts as correct.
  - Selected label = filled pin + ring + bold row (not colour alone). Auto-select the next unplaced label after placing one.
  - Image changes redraw automatically (remove "Refresh picture"). Empty state with an image picker button and the flask illustration.
  - Warn when two targets overlap (their circles intersect), since students can't tell them apart.
- **Student side:** same stage; pins snap-animate into place; on small screens the image can be tapped to zoom.
- **Data:** keep `x`, `y`, `radius` as 0–1 fractions in JSON (no migration); the editor just shows percent.

**Status**
- Done: stage sized to the image (`width: fit-content`, `align-self: flex-start`), so pins line up in the editor and student view. Teacher editor rebuilt for this question type only: label rows (number, text, Placed / Not placed, remove), click to place with auto-advance to the next unplaced label, drag pins, arrow-key nudge, answer circle drawn on the picture with Small / Medium / Large + slider + %, overlap warning, "Exact positions" in percent (no spinners), empty state, auto-redraw when the Image URL changes ("Refresh picture" removed).
- Done (round 2): pins, answer circles and the student crosshair now sit in `.q-hot__frame`, a box exactly the size of the rendered picture, in both the editor and the student widget. Before, they were positioned against the outer stage, which could be wider or taller than the picture (minimum sizes, stretching), so the spot the teacher saw was not the spot students had to click.
- Done: **any picture** works for this question type. The editor has its own Picture panel: paste a link (http is upgraded to https; Google Drive and Dropbox share links are turned into direct image links), upload a file, paste a screenshot, or drop a picture on the box. Uploads are scaled and compressed (WebP/JPEG, about 30 KB max) and stored in the test, since a published test must fit in one Sheet cell (49,000 characters). `safeImageUrl` now accepts raster `data:image/...` URLs (not SVG). The generic Image row is hidden for this type.
- Teachers should re-check answer keys made with the old editor: positions typed by hand or adjusted to "look right" may be off.
- Still to do: show placed labels on the picture in results, grading and PDF; tap-to-zoom for students; check every view against the acceptance criteria.

**Acceptance criteria**
- [ ] With an image narrower than the card, wider than the card, and portrait, each pin sits on the same spot of the picture in the editor, runner, results, grading view and PDF (at 360, 768 and 1366 px).
- [ ] A teacher can place, drag, nudge, rename and delete labels without typing numbers.
- [ ] No horizontal overflow in the editor at 360 px; no number spinners over digits.
- [ ] Everything works by keyboard; the selected label is clear without colour.

## V4-03 — More question types

Follow the v3 per-type checklist: `js/lib/qtypes/<type>.js` (normalize, validate, grade, format), `js/views/widgets/<type>.js`, `js/views/admin/editors/<type>.js`, export rendering, `scripts/validate-tests.mjs`, a sample in `data/tests/`, a JSON example in `docs/guide.md`, unit + E2E tests.

| Type | What the student does | Grading | Priority |
|---|---|---|---|
| `multipart` — Multi-part problem | One stem (text, data table, image) with parts a, b, c… each of any auto-graded type | Sum of parts; each part graded by its own type | High |
| `naming` — Name ↔ formula | Writes the name for a formula, or the formula for a name (ionic, covalent, acids, hydrates) | Auto. Normalizes case, spacing, "mono-", Roman numerals; accepts a list of names | High |
| `dropdown` — Inline dropdown cloze | Picks words/values from dropdowns inside a sentence or equation | Auto, per blank | High |
| `dimensional` — Dimensional analysis | Builds a chain of conversion factors (fraction tiles with value + unit), units cancel visually, enters the final answer | Auto: final value (tolerance) + units; optional credit for a valid chain | High |
| `nuclear` — Isotope / nuclear notation | Fills mass number, atomic number and symbol; or completes a nuclear equation (α, β, γ) | Auto. Conservation checked | Medium |
| `reaction` — Predict the products | Types the product side (and states) of a reaction, or a net ionic equation | Auto. Reuses formula parser; order-free, coefficients optional or required | Medium |
| `vsepr` — Molecular shape | Picks electron geometry, molecular geometry and bond angle from illustrated choices | Auto, credit per field | Medium |
| `datatable` — Complete the table | Fills cells in a data table (e.g. protons/neutrons/electrons, ICE table) | Auto per cell, tolerance per column | Medium |
| `molarmass` — Molar mass / calc with work | Enters the answer plus optional work steps; the built-in molar-mass checker validates the formula used | Auto on the final answer; work shown to the teacher | Medium |
| `imagechoice` — Image choice | Picks one or more images (glassware, hazard symbols, particle diagrams) | Auto (like `mcq`/`multi`) | Medium |
| `particles` — Particle diagram | Picks or builds a particle-level picture (solid/liquid/gas, mixture, before/after a reaction) by placing atoms in a box | Auto: counts per species and phase | Low |
| `titration` — Virtual titration | Adds titrant from a burette on a simple simulated curve, then reads the endpoint volume / pH | Auto within tolerance | Low |
| `estimate` — Slider | Drags a slider to a value (pH, temperature, percent) | Auto within tolerance | Low |

- **Per-question extras for every type:** confidence rating (optional, "how sure are you?", shown in Insights), hint that costs points (optional), explanation shown after release (exists for some types; make it universal).
- `multipart`, `naming`, `dropdown` cover the most common worksheet patterns; do them first.
- Add auto-graded types to games where they fit (`naming`, `nuclear`, `vsepr`, `dropdown` in Classic / Survival / Lightning; `naming` pairs in Match-Up and Flashcards).
- `sketch` (draw on a canvas) is **skipped** for v4: there is nowhere good to store images.

**Acceptance criteria**
- [ ] Each type can be authored in the builder and in JSON, validated, taken, auto-graded (or teacher graded), reviewed in results and feedback, exported to PDF, and used in pools/bank.
- [ ] Keyboard and screen-reader support for every new widget (no drag-only interaction).

**Class leaderboard (only when the game option is on):**
- Shown only if the test has `gameMode: true` **and** `gameOptions.leaderboard: true`. Otherwise nothing is sent and no leaderboard appears.
- Per test and per game: top 10 best scores, plus the student's own rank. On the game picker and the end screen.

- [ ] Untimed mode removes all time pressure, including speed points.
- [ ] With the leaderboard off, games send nothing to the backend. With it on, they send only the final score.
- [ ] A test without game mode never shows or accepts leaderboard scores (checked server-side).

## V4-07 — Admin accounts, classes and rosters

**Admin accounts (do first; other features depend on it)**
- Admins sign in with Google, same as students. No password: if the signed-in email is on the admin list, the admin panel opens and every admin action (editing tests, grading, settings) just works.
- Backend verifies the admin's ID token (reuses `verifyStudent_` from v3) instead of `ADMIN_KEY`. The client sends the token automatically with every admin request; there is no password field for listed admins.
- Upgrade period: `ADMIN_KEY` still works for anyone not yet on the list. A listed admin is never asked for it (no prompt, nothing to paste); the client fills the auth in from the Google sign-in. After the upgrade, `ADMIN_KEY` can be removed.
- Token expiry: when the Google token expires mid-session, the client refreshes it silently (or re-prompts Google sign-in, never a password) and retries the request, so unsaved work isn't lost.
- Optional: when an admin is added, also share the backing Google Sheet with them as an editor (`SpreadsheetApp.addEditor`), so they can open the raw sheet too; removing them revokes it. Needs the Drive permission; off unless the owner turns it on.

**Admin list (easy to edit)**
- One source of truth: the `Admins` sheet, one row per admin: `Email` | `Role` (`owner` / `admin`) | `Added by` | `Added at`. Add an admin by typing an email in a new row; remove one by deleting the row. No redeploy, no script properties, no code change.
- Same list is editable in **Settings → Admins** (owner only): add by email, remove, change role. Writes the same sheet.
- Emails are trimmed and lower-cased when read, so stray spaces or capitals don't lock anyone out. Blank rows are ignored.
- First deploy: if the `Admins` sheet is empty or missing, it's created and seeded from the `ADMIN_EMAILS` script property (comma list), with the first email as `owner`. After that the sheet wins; the property is only a fallback if the sheet is emptied.
- The owner can't remove themselves or the last owner (prevents a lockout).
- Changes apply on the admin's next request (the list is read per request, or cached ≤ 60 s).
- `DEPLOYMENT.md` gets a short "Add or remove an admin" section (open the sheet → `Admins` tab → add/delete a row).
- Every admin action records the admin's email (activity log, "Graded by", "Added by" in the bank).
- Optional per-test owner: tests show "Created by"; any admin can still edit (shared, per decision 4).

**Classes and rosters**
- A **class** = name, period, admin(s), list of student emails. Create by pasting emails or importing a CSV (Google Classroom / Aeries export).
- Assign a test to one or more classes. Grading, Insights, Mastery and the live monitor can filter by class.
- Students not on any roster can still take a test unless the test is set to "Roster only".
- Accommodations can be set per class member from the roster screen.

**Backend:** `Admins`, `Classes` sheets; actions `listAdmins`, `saveAdmin`, `listClasses`, `saveClass`, `deleteClass`; `getTest`/`submit` check "Roster only".

**Acceptance criteria**
- [ ] A listed admin signs in with Google and can edit tests, grade and change settings without ever typing a password.
- [ ] Adding an email row to the `Admins` sheet (or in Settings) gives that person admin access on their next request, with no redeploy.
- [ ] Two admins signed in on different machines are recorded separately in the log and in "Graded by".
- [ ] Removing an admin stops their access on their next request.
- [ ] A "Roster only" test refuses a student who isn't on an assigned class, server-side.

## Running v4 across sessions

v4 is too big for one sitting. It is split into **sessions**, each sized for about one 5-hour Claude quota. Every session must leave the project working.

**Rules for every session**
1. Start: read this plan, `docs/v3/v4-progress.md` and the last session's handoff notes. Pull `v4`.
2. Work on a branch `claude/v4-sNN-<topic>` cut from `v4`. Merge back into `v4` (PR) at the end. `main` only gets v4 when it's released.
3. Unfinished features hide behind `FEATURES` flags (V4-08) so `v4` always runs.
4. Before ending: `npm run test:all` and `npm run validate:tests` green; commit; push; update `v4-progress.md` (done, in progress, next step, any surprises). Stop early rather than leave things half-wired.
5. Contracts first: when a session adds backend actions, columns or test JSON fields, write them into `docs/ARCHITECTURE.md` ("V4 contracts") in the same session.
6. Large chunks can use the `plan-and-delegate` approach (subagents for independent question types, games or views), with the main session reviewing and running tests.
