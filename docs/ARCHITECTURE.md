# ChemistryWorks — Architecture

The current state of the app: data shapes, module interfaces and backend contracts. If code and this file disagree, fix one of them in the same change. The contracts for v2 to v5, as they were written at the time, are in `docs/archive/architecture-v5.md`; where they differ from this file, this file wins.

## Stack

- Static site, **no build step**. Native ES modules (`<script type="module">`), plain CSS, no framework. GitHub Pages publishes the runtime files (`.github/workflows/pages.yml`, `docs/hosting/github-pages.md`). `netlify.toml` is kept only for rollback.
- KaTeX 0.16.11 with mhchem and auto-render from cdnjs (globals `katex`, `renderMathInElement`). Views call `renderMath(root)` from `js/ui.js`, never KaTeX directly.
- Google Identity Services for sign-in (`js/lib/auth.js`). Demo sign-in exists only when no client ID is configured (see Admin access and Identity).
- Backend: one Google Apps Script web app (`apps-script/Code.gs`) over a Google Sheet. It stores published tests, submissions, classes, tags and everything else listed under Sheets, and talks to Google Classroom as the deploying account.
- Installable and offline-tolerant: `manifest.webmanifest`, `sw.js`, `sw-list.js` (generated).
- Tests: Node's built-in runner (`node --test`) for unit tests; Playwright (`playwright` 1.63) for browser tests; `axe-core` for the accessibility scan. No runtime npm dependencies.
- Release files: `js/version.js` (`SITE_VERSION`, `BACKEND_VERSION`), `package.json` version, `changelog/<version>.md` and `changelog/index.json` (see `CLAUDE.md`). `npm run stamp:version` writes the version into `index.html` and regenerates `sw-list.js`; a unit test fails while they are out of step.

## View contract

```js
// js/views/<name>.js
export function render(root, ctx, params) { /* build DOM in root */ return cleanupFn /* optional */; }
export const styles = ['hub'];            // or export function styles(params): stylesheets this view needs (css/<name>.css)

ctx = {
  config,                    // CONFIG
  user,                      // getter: { name, email, picture|null, provider: 'google'|'demo', idToken? } | null
  signOut(),                 // signs out and returns to landing
  navigate(view, params),    // see views below
  openTest(code),            // async: load by code and open the runner (student mode)
}
```

Views in `VIEWS` (`js/app.js`): `landing`, `runner`, `results`, `feedback`, `submitted` (static imports) and `unavailable`, `game`, `admin`, `profile`, `class` (lazy loaders). `navigate()` awaits the view module, its `styles`, and `preloadQuestionTypes(params.test.questions)` before the first render, so a view never paints unstyled. After rendering, `announceView` writes the view name to the polite live region `#view-announcer` and moves focus to the view title (`h1`, `[data-view-title]` or the first `h2`) unless the view already took focus. `#app` is not a live region.

URL state: `?code=<CODE>` opens a test (after sign-in); `?admin=true` opens the admin panel; `?view=profile`; `?view=class&id=<classId>`; `?view=feedback` is reached from the profile.

Params: `runner` `{ test, source: 'bundled'|'published'|'draft', preview? }`; `results` `{ test, grade, payload, submission, preview? }`; `game` `{ test, mode }`; `unavailable` `{ reason, ... }`.

## Configuration and kill switches

`js/config.js` merges, left to right: `DEFAULTS`, `js/config.local.js` (written by the Pages workflow from repository variables; a missing file is fine), `window.CHEMISTRYWORKS_CONFIG` (used by e2e). Keys: `APP_NAME`, `GOOGLE_CLIENT_ID`, `GAS_WEB_APP_URL`, `SHEET_URL`, `ALLOW_DEMO_SIGNIN`, `ALLOWED_EMAIL_DOMAINS`, `DEFAULT_MODE`, `KILL_SWITCHES`.

`KILL_SWITCHES = { classHub, gameModes, studentSync }`, all `false`, merged key by key. `killed(name, config = CONFIG)` is true only when the value is exactly `true`; an unknown name is `false`. There is no URL override and no feature-flag system.

- `classHub`: hides class pages, assignments, the stream and notifications for students, and the Class Hub nav for teachers. Student home still works.
- `gameModes`: hides the mode switcher; the runner stays in Study.
- `studentSync`: `sync.js` never starts and no `syncProgress` call is made.

## Test JSON schema

```jsonc
{
  "code": "CHEM101",              // required, normalised to /^[A-Z0-9_-]{2,32}$/
  "title": "Foundations",         // required
  "description": "",
  "timeLimitMinutes": 20,         // null = untimed
  "shuffleQuestions": false, "shuffleOptions": false,
  "showResults": true,            // student sees the score after submitting
  "showCorrectAnswers": true,     // per-question review with answers and explanations
  "allowModeToggle": true, "defaultMode": null,   // runner layout 'focus' | 'scroll'
  "passingPercent": null,
  "singleSubmission": false, "requireAllQuestions": false,
  "games": [], "gameOptions": {}, // allowed study/game modes (see Study and game modes)
  "opensAt": "", "closesAt": "",  // ISO text with offset; empty = no window
  "late": { "until": "", "penalty": { "type": "percent|points", "value": 10 } },
  "announcement": "", "classes": [], "rosterOnly": false,
  "sections": [{ "id", "title", "instructions" }],
  "references": [{ "id", "type": "text|image|resources", "title", ... }],
  "questions": [ /* Question[], at least 1, unique ids */ ]
}
```

Common question fields: `id` (required, unique, `/^[A-Za-z0-9_-]+$/`), `type`, `text` (may contain KaTeX `$...$` and `$\ce{...}$`), `points` (default 1, > 0), `explanation`, `section`, `image: { url, alt }` (alt text required), `tags: string[]` (ids, at most 10), plus the type's own fields. Algorithmic questions use variables and per-student instances (`instance: { seed, drawn }`). `normalizeTest` never mutates its input; `validateTest` returns `{ valid, errors, warnings? }` with errors prefixed by a location (`Question 3 (q3): ...`). An unknown `type` is a validation error.

`answers = { [questionId]: answer }`. Unanswered means the key is missing, `null`, `""` after trim, `[]` or `{}`.

### The 42 question types

Every type is registered through one registry (see TypeDef). Groups are the builder menu groups. `*` = teacher graded, `^` = `layout: 'wide'` (full-width in the split layout).

| Group | Types |
|---|---|
| Basics | `mcq`, `multi`, `truefalse`, `numeric`, `multipart`, `datatable`, `short*`, `open*` |
| Chemistry | `formula`, `balance`, `econfig`, `ptable^`, `sigfigs`, `naming`, `dimensional`, `nuclear`, `reaction`, `vsepr`, `molarmass`, `titration`, `estimate`, `ionicformula`, `isotopemass`, `ionbuilder`, `heatcurve`, `oxidation`, `solubility`, `bohr`, `molbuild^`, `gaslaw` |
| Match & sort | `matching^`, `ordering^`, `fillblank`, `categorize^`, `dropdown` |
| Diagrams & graphs | `hotspot^`, `imagechoice`, `particles`, `lewis^`, `structure^`, `orbital*`, `graph^` |

Each type's fields, answer shape and key are shown by its fixture, `test/fixtures/types/<type>.json` (`question`, `correct`, `wrong`, optional `partial`), and by its definition's `normalize` and `validate`. `structure` is teacher graded per question when `studentCharges` is true. `data/tests/DEMOV5.json` has one question per newer type.

### Scoring

`grade(q, answer, H)` of each definition returns `{ fraction, full }`; `gradeQuestion` scales by `points` and rounds to 2 decimals. `isCorrect` is true only for full points. `percentage = (scoreAchieved / scoreTotal × 100).toFixed(2)` as a string, `"0.00"` when the total is 0.

- Types with `partialCredit` score `correct parts / parts` (matching pairs, ordering positions, fill-blank blanks, categorize items, structure bonds and atoms); `multi` scores `max(0, (correctSelected − wrongSelected) / correctCount)`.
- `numeric` parses with `parseNumber` (`6.02e23`, `6.02x10^23`, unicode minus, thousands commas, a trailing unit that equals the question's unit). Correct within `tolerance` (absolute) or `tolerance`% of the key, plus a 1e-9 relative epsilon.
- `formula` compares `normalizeFormula` output (subscripts, charges and hydrate dots normalised).
- Manual types (`short`, `open`, `orbital`, and `structure` with `studentCharges`) score 0 with `needsGrading: true` until a teacher grades them. `gradeTest` also returns `pendingCount` and `pendingPoints`. The submission row gets `Status = Needs grading`; `saveGrade` stores per-question points in `Grades (JSON)`, recomputes `Final Score` and sets `Status = Graded`. Teachers may override auto-graded points.
- Answer keys ship to the browser. There is no server-side grading and no key stripping.

## TypeDef

A type is three modules plus a fixture:

| Module | Path | Loaded | Holds |
|---|---|---|---|
| Definition | `js/lib/qtypes/<type>.js` | statically, by `js/lib/qtypes/index.js` | pure logic, no DOM, runs in Node |
| UI | `js/views/qtypes/<type>.js` | lazily, `loadTypeUI(type)` | `render`, optional `review` |
| Editor | `js/views/admin/editors/<type>.js` | lazily, `loadTypeEditor(type)` | `edit` |
| Fixture | `test/fixtures/types/<type>.json` | tests only | answers for the conformance test |

A definition registers itself with `registerType(def)`. Registry API (`js/lib/qtypes/registry.js`): `registerType`, `typeDef(type)` (non-null for all 42), `registeredTypes()`, `typeLayout(type)`, `loadTypeUI`, `loadTypeEditor`, `typeUI`, `typeEditorModule`, `hasTypeUI`, `preloadQuestionTypes(questions)`, `typeCssNames(type)`. No consumer switches on a type name (`test/unit/qtype-switches.test.mjs` enforces it).

```js
{
  type: 'mcq', label: 'Multiple choice', shortLabel: 'MCQ',
  group: 'Basics' | 'Match & sort' | 'Chemistry' | 'Diagrams & graphs',
  manual: false,                                  // true = teacher graded
  isManual(q),                                    // optional, per question; replaces manual when present
  layout: 'split',                                // optional: 'split' (default) | 'wide'
  normalize(q, H),                                // mutate in place: defaults, coercion, tags kept
  validate(q, where, errors, H),                  // push `${where}: ...`; never throw
  blank(base) -> question,                        // builder template; base = { id, type, text, points }
  isAnswered(q, answer) -> boolean,
  grade(q, answer, H) -> { fraction, full },      // manual types return { fraction: 0, full: false }
  format(q, answer) -> string,                    // the answer as text (results, CSV, grading)
  keyText(q) -> string,                           // the correct answer as text
  correctAnswer(q) -> any,                        // stored as correctAnswer in graded results
  toPdf(q, answer, H) -> string[],                // optional; default [format(q, answer)]
  resultExtras(q),                                // optional; extra fields copied onto each graded result row (open adds rubric)
  displayText(q),                                 // optional; fillblank shows blanks as ____(n)
}
```

`H` is the helper bag callers pass in so type modules never import `schema.js` or `grading.js`: `{ normalizeQuestion, validateQuestion, gradeQuestion, isAnswered, formatAnswer, correctAnswerText, parseNumber }`.

UI module default export: `{ type, render(widgetCtx) -> { el, refresh(answer), focus(), destroy?() }, review?(q, answer, { key, size }) -> Node | null }`, with `widgetCtx = { q, api: { get(id), set(id, value, { debounce }) }, readOnly, uid }`. The value `render` writes with `api.set` is the answer value every definition function receives. Every widget root has `data-testid="<type>-widget"`. Editor default export: `{ type, edit(editorCtx) -> Node }`, `editorCtx = { q, redraw, changed, uid }`. Both loaders reject unknown types with `unknown_type:<type>`, cache their promise, and are static maps so paths stay analysable.

Shared pieces: `js/lib/qtypes/shared.js` (`normOptions`, `validateList`, `optionText`, type guards), `js/views/qtypes/shared.js` (option pictures, typing-help box, insert bar, `optLabel`), `js/views/admin/editors/shared.js` (ids, `parseSci`, variables, image control, format-help field). The widget and the static diagram of `lewis`, `structure` and `orbital` share drawing code in `js/views/lewis-view.js`, `structure-view.js` and `orbital-view.js`; hotspot drawing is `js/views/widgets/hotspot-stage.js`.

Conformance (`test/unit/qtype-conformance*.test.mjs`, `test/e2e/qtype-conformance.test.mjs`): `validate` returns no errors; `grade(correct).full`; `grade(wrong).fraction === 0`; `0 < grade(partial).fraction < 1` where present; `format`, `keyText`, `toPdf` give text; the question renders in the runner and every mode and shows in results and the PDF view with no console error. For manual types `wrong` is a blank answer and `grade` is never full.

Layout: `registerType` fills `layout: 'split'`. `qSplit(q, promptEl, ...answerEls)` (`js/views/q-split.js`, testid `q-split`) builds `.q-split[data-layout]`; from 1200px a `split` type is a two-column grid, a `wide` type and anything under 1200px stays one column.

## Module interfaces

### js/lib/schema.js
`QUESTION_TYPES`, `MANUAL_TYPES`, `TYPE_LABELS`, `MAX_TAGS_PER_QUESTION`, `normalizeTest(raw)`, `normalizeQuestion`, `validateTest(test, { knownTagIds }?) -> { valid, errors, warnings }` (`warnings` only when `knownTagIds` is passed: unknown tag ids), `blankQuestion(type, id)` (throws `RangeError` for an unknown type), `nextQuestionId`, `blankTest`.

### js/lib/grading.js
`parseNumber(str, { unit })`, `isAnswered`, `gradeQuestion(q, answer)`, `gradeTest(test, answers, opts) -> { scoreAchieved, scoreTotal, percentage, correctCount, answeredCount, questionCount, pendingCount, pendingPoints, results: [{ questionId, questionText, type, givenAnswer, givenAnswerText, correctAnswer, correctAnswerText, isCorrect, answered, pointsEarned, pointsPossible, needsGrading?, rubric?, ... }] }`, `formatAnswer`, `correctAnswerText`, `pdfLines(q, answer)` (the type's `toPdf`, else `[formatAnswer]`). All dispatch through the registry.

### js/lib/submit.js
```js
buildPayload({ test, grade, user, startedAt, submittedAt, flags }) -> Payload
// { submission_id, student_name, student_email, test_code, test_title, score_achieved, score_total, percentage (string),
//   responses: grade.results, needs_grading, single_submission, instance?, time_limit_applied?,
//   started_at, submitted_at, duration_seconds,
//   flags: { tab_switches, auto_submitted, mode: 'focus'|'scroll', game_mode?, questions? } }
submitResults(payload, { config, fetchImpl, ... }) -> { gas: 'sent'|'final'|'failed'|'skipped', finalError?, queued }
flushOutboxResult(...) -> { sent, final: [{ submission_id, error }] };  flushOutbox(...) -> count sent
getOutbox(), getLocalResults()
```
`flags.game_mode` is the last study or game mode (`attempt.js` `toSubmission` sets it; omitted for Study). `flags.questions` is `{ questionId: note }` for questions the student flagged for the teacher.

Submit rules: the client POSTs to `GAS_WEB_APP_URL` with `Content-Type: text/plain;charset=utf-8` (a simple request, no preflight), a JSON string body, normal CORS, and reads the reply. The body is the payload plus `submission_id` and, at send time only, `idToken` (never stored in the outbox). `submission_id` is the idempotency key: a repeat replies `{ result: 'success', duplicate: true }`. 15 second timeout.

| Reply | Result |
|---|---|
| `{ result: 'success' }` (including `duplicate`) | Done: remove from the outbox, keep in `localResults` |
| Final error: `closed`, `not_open`, `not_on_roster`, `single_submission`, `submission_too_large`, `invalid_request`, `invalid_email`, `missing_*`, `unauthorized` | Show the message; do not queue |
| Network error, timeout, non-JSON, `server_error`, `busy`, `rate_limited`, `invalid_token` | Keep in the outbox with the same id; "Not sent yet, we'll retry" with a Retry button |

`invalid_token` retries after one silent token refresh; otherwise the item waits until the student signs in. The outbox (`outbox`) flushes on page load, on `online`, on Retry and on a backoff timer. Only success or a final error removes an item. There is no Netlify channel.

### js/lib/api.js
One exported wrapper per backend action, built on `adminCall` / `publicCall`. Each is `async fn({ gasUrl, adminKey?, idToken?, fetchImpl, ...fields })`, never throws, and resolves `{ ok: true, data } | { ok: false, error, unavailable? }`. Older wrappers keep their own shapes (`pingBackend`, `fetchPublishedTest`, `fetchPublishedTestResult` (returns `tagIndex`), `publishTest(test, { gasUrl, adminKey, tagDefs, fetchImpl }) -> { ok, tags }` or `{ ok: false, error: 'unknown_tag', ids }`, `listPublishedTests`, `fetchResults`, `fetchFeedback({ gasUrl, submissionId, idToken })`). With no `gasUrl`, or `unavailable: true` (old backend), callers keep working from local storage and show the "Not synced" chip. Student calls add the signed-in user's `idToken` (`getFreshIdToken()`). Admin calls send `idToken` and, when set, `adminKey`.

### js/lib/store.js
`resource(name, { fetch, key, ttl }) -> { get({ force }), refresh(), patch(fn), optimistic(change, request), subscribe(fn), peek() }`. One in-flight request per resource key; a `sessionStorage` warm start under `cw:store:<name>[:<key>]`; `ttl` default 60 s; cleared on sign-out. `optimistic` applies the change, awaits `request()`, and on failure rolls back and toasts an error with Retry. Resources: `tests`, `counts`, `results`, `classes`, `bank`, `profile`, `hub`, `tags`.

### js/lib/css-loader.js
`ensureCss(name, { media }?) -> Promise<void>` loads `css/<name>.css`. The URL is built from `import.meta.url` (relative, so it works under the `/ChemistryWorks/` Pages path) and ends in `?v=<SITE_VERSION>`. Idempotent (a `data-css` attribute), never rejects (resolves on load, error or after 3 s). `pendingCss(names)` returns `null` when everything is loaded, else a promise, so `navigate()` stays synchronous when it can. `index.html` links only `base.css` and `landing.css`; print is linked once with `media="print"`. `appearance.css` also holds text-size, density, dyslexia and reduce-motion rules (loaded by `theme.js` when one is non-default); `tools.css` holds font and spacing rules (loaded by `applySettings`). Per type: `typeCssNames(type)` is `runner`, `qtypes`, `qt-<type>` (when the type has a sheet) and `diagrams` for `lewis`, `structure`, `orbital`.

| Owner | Stylesheets |
|---|---|
| Runner, modes, tools | `runner`, `modes`, `game`, `tools`, `references` |
| Results, submitted, feedback | `results`, `feedback`, `export`, `diagrams` |

### js/lib/dates.js

## Student attempt (`js/lib/attempt.js`)

One attempt per student per test, shared by the runner and every mode. Stored under `progress:<email>:<CODE>`: `answers`, `confidence`, `hints`, `flagged`, `index`, `startedAt`, `tabSwitches`, `mode` (runner layout), `updatedAt`, `title`, `scratch`, `struck`, `flagNotes` (student tools), `lastMode` (default `'study'`), `modeState { <modeId>: object }` (each mode's resume data, under 4 KB), `wrong [qid]` (feeds Mistake Review), `v: 5`.

`openAttempt(test, { email, preview }) -> attempt`: `questions` (instantiated in test order), `get(id)`, `set(id, value)` (an empty value removes the answer; autosave + `subscribe`), `isAnswered`, `flag(id, on)` / `isFlagged`, `next({ filter })`, `answeredCount`, `total`, `results() -> { [qid]: { correct: true|false|null } }`, `lastMode`, `setMode(id)`, `subscribe(fn)`, `save()` (debounced 400 ms; immediate on `setMode`, `pagehide`, `visibilitychange`; never in preview or after submit), `grade()`, `toSubmission({ auto, layout, tools, submittedAt }) -> { grade, payload }`, `destroy()`, `unsync()`. Correctness is shown (`correct` true/false) only when `showResults !== false` and `showCorrectAnswers !== false` and the type is auto-graded; otherwise `correct: null` and modes show "Saved".

## Study and game modes

- Registry `js/lib/modes/index.js`: `MODES`, `modeById(id)`, `modesForTest(test, attempt?) -> [{ mode, available, reason }]` in `order`. `study` is always first and available. Ids: `study, classic, lightning, survival, flashcards, mistakes, tower, boss, matchup, quizshow, race, bingo`.
- Definition: `{ id, title, blurb, icon, order, pacing: 'self'|'timed'|'lives'|'none', scoring(attempt, events) -> { score, detail }, minQuestions, available(test) -> { ok, reason? }, render(host, attempt, ctx) -> { destroy() } }`. Logic is `js/lib/modes/<id>.js`; DOM is `js/views/modes/<id>.js`; the shell is `js/views/mode-shell.js`.
- `ctx = { widgetFor(q), feedback(q, result), onEnd(summary), sound, reducedMotion }`; `summary = { modeId, score, answered, correct, total, durationMs }`. A mode never adds, drops or swaps questions. Teacher-graded types are answered in place ("Saved", no points, no life lost).

## Backend (`apps-script/Code.gs`)

`VERSION` in `Code.gs` and `BACKEND_VERSION` in `js/version.js` stay together; the admin banner shows when the deployed backend is older than `BACKEND_VERSION`. Replies are `ContentService` JSON: `{ result: 'success', ... }` or `{ result: 'error', error, ref? }`.

### Entry points
- `doGet`: `ping` -> `{ result: 'success', version }`; `getTest&code=` -> `getTest_` (older shape for refusals: `{ error, opensAt?, closesAt?, title? }` with no `result`, which `fetchPublishedTestResult` depends on, so clients check `error` first). Anything else: `unknown_action`.
- `doPost`: JSON body routed by `action`. A body with no action (or `submit`) is a submission. Uses `LockService` where writes need it; `withLock_` is re-entrant within a request. Submissions, live pings, error reports and log lines take no script lock.
- Catch-alls log the full `String(err)` and stack to the `Errors` sheet (`Page` = `backend:<action>`, `Message` = `[<ref>] <message>`, `Detail` = stack) and reply `{ result: 'error', error: 'server_error', ref }` (6 lowercase base-36 characters). The error text never reaches the client.

### Authentication
- **Public** (no token): `ping`, `getTest` (GET), `getStudentStatus`, `getLeaderboard`, `reportError` (token optional), `progressPing`.
- **Student** (`idToken`, via `verifyStudent_`, returns `{ email, name }` from the token; a client email is never used when a token is present): `submit`, `getTest` (POST; the only way to read a roster-only test), `getFeedback` (token email must equal the row's email), `getStudentProfile`, `saveStudentProfile`, `syncProgress`, `getClassHub`, `markNotificationsRead`, `submitGameScore`.
- **Admin** (`requireAdmin_`): a Google ID token whose email is on the `Admins` sheet (seeded from `ADMIN_EMAILS`), or the `ADMIN_KEY` script property sent as `adminKey` (constant-time compare; after 10 failures in an hour, counted in `CacheService`, replies `locked`). Writes are logged to `Log`. Roles are `owner` and `admin`; a key caller reports role `owner` only while no owner exists.
- Tokens are checked against Google `tokeninfo` (cached up to 6 hours): audience must be `GOOGLE_CLIENT_ID`. Without a token, a submission is accepted only when script property `ALLOW_UNVERIFIED_EMAIL` is `true` (local and demo only), else `unauthorized`.
- Every user-supplied cell goes through `text_()` (prefixes `'` before a leading `=`, `+`, `-` or `@`); a backend test writes `=HYPERLINK("x")` to every string field of every action.

Due times are compared in the script time zone; `dueAt` is ISO text with offset; turning in at exactly `dueAt` is on time. ### Triggers, retention, diag and setup
- `setupTriggers()` installs the time-driven triggers and is safe to run repeatedly (it removes its own earlier triggers by handler name). ## Identity and admin access

- Students sign in with Google (or the demo form when Google is not configured). The submission's stored email and name come from the token; if the token has no `name` claim the body's name is kept as display text only, through `text_()`. The single-submission and roster checks use the stored email. Rows carry `Identity` = `verified` or `unverified`; grading and results show an "Unverified" pill (`identity-mark.js`). A repeat `submission_id` replies `duplicate: true` before any identity check.
- Admin sign-in is Google only: the client sends the ID token and the backend checks the `Admins` sheet (`whoami`). There is no access code. `ADMIN_KEY` is only the backend's Sheet credential for set-up and recovery (before the sheet has an owner); it is typed into admin -> Settings -> "Sheet key", kept in session storage and never needed to open the panel.
- `demoAdminAllowed(config)` (`js/lib/admin-session.js`) is true only when `GOOGLE_CLIENT_ID` is empty; it is impossible when an ID is set (unit test). Local dev and e2e set `GOOGLE_CLIENT_ID: ''`. The demo admin only talks to mock backends.

## Tags

**Two homes.** A tag is local (browser storage, like a draft) until a published test uses it. Publishing writes it to the `Tags` sheet; from then on the Sheet is the source of truth. Only the owner edits a Sheet tag; any admin can use it. Local tags never call the backend. An `ADMIN_KEY` caller has no email, so it owns Tag rows and tests whose owner is empty.

- `id`: `tg_` + 6 lowercase base-36 characters (`/^tg_[0-9a-z]{6}$/`), made in the browser, never changed. `color`: `blue | violet | teal | green | orange | rose | gray`; each maps to tokens `--tag-<color>-bg` / `--tag-<color>-ink` in `css/base.css` (light and dark, 4.5:1 checked in `test/unit/tags.test.mjs`). `name` max 40 characters, `description` max 200, both through `text_()`.
- `q.tags: string[]` holds ids only, at most 10 per question, de-duplicated. `validateTest` warns on an id that is neither local nor on the Sheet (with `knownTagIds`) and errors above 10. The importer accepts tag names and maps them to ids (`mapTagNames`, `applyTagNames`; the builder opens `import-tags-modal` for the rest).
- `publishTest` takes `tagDefs: [{ id, name, color, description }]` for every tag a question uses. In one locked write a new id becomes a Sheet row owned by the publisher (`firstTestCode`); an id already on the Sheet keeps the Sheet's name and colour unless the publisher owns the row. An id in neither `tagDefs` nor the Sheet replies `unknown_tag` with `ids` and nothing is published. Success adds `tags: [{ id, ownerEmail, name, color, description, applied: 'created'|'updated'|'unchanged'|'sheet_wins' }]`; the builder sets `onSheet: true` from it. Deleting or unpublishing a test never deletes a Sheet tag.
- Actions: `listTags` -> `tags: [{ id, ownerEmail, ownerName, name, color, description, firstTestCode, createdAt, updatedAt, mergedInto, usage: { questions, tests } }]` (non-deleted rows; usage counted over published tests against the live end of any `mergedInto` chain); `saveTag { tag }` (owner only, existing Sheet tags only, else `not_on_sheet`); `deleteTag { id }` (owner only, soft delete: `deletedAt`); `mergeTags { from, into }` (owner of both, `from !== into`: in one locked pass it rewrites the owner's published tests, de-duplicating, and sets `from.mergedInto` and `deletedAt`; other owners' tests keep the old id, which resolves through `mergedInto`).
- `tagIndex: { [id]: { name, color } }` is in `getTest` (GET and POST), `getTestFor_` and `getFeedback` replies for the ids the test uses. A deleted tag keeps its name; a merged id resolves to its target; a missing id shows "Unknown tag". Students and the PDF export read names from `tagIndex` (`studentTag(id, tagIndex)`); admin views read the `tags` store resource (`adminTag(id)`). Raw ids are never shown. `fetchPublishedTestResult` returns `tagIndex`; `loadTest` and `getFeedback` replies feed `rememberTagIndex` / `recalledTagIndex`.
- UI: tag picker, filter bar and "Apply tag" dialog in `js/views/admin/builder/tag-picker.js`; Admin -> Tags is `js/views/admin/tags.js` (nav id `tags`). Per-topic summaries: `js/views/tag-summary.js` (`tagSummary(rows, opts)`, `topicFilter`); `matchesLibraryFilter` takes `tag` and `tagsByCode`. Student views count released rows only; teacher views (`adminTagStats`) count all.

## Google Classroom

**Who it runs as.** The script runs as the deploying account (`executeAs: USER_DEPLOYING`). | `previewGradeSync` | `{ assignmentId }` | `{ courseWorkId, courseWorkState, maxPoints, syncAccount, counts, rows: [{ email, name, points, possible, released, target, classroomDraft, classroomAssigned, lastSent, action }] }` |
| `syncGrades` | `{ assignmentId, overwrite?, emails?, cursor? }` | `{ done, cursor, synced, failed, skipped, results: [{ email, status, error? }] }` |

`postToClassroom: true` creates coursework with the assignment's title, `description` = instructions + the test link (`?code=<CODE>`), `maxPoints` = the test's total points, the due date and time, `workType: 'ASSIGNMENT'` and `materials: [{ link }]`. `state` is `DRAFT` when `publishAt` is in the future (the hourly `publishDueClassroomWork` publishes it once due), else `PUBLISHED`. An assignment that already has a `classroomCourseWorkId` updates that coursework; if it was deleted in Classroom the next post creates a new one. Without `postToClassroom`, `saveAssignment` never calls Classroom.

**Grade rules.** Grade = `round(fraction × maxPoints, 2)`, from the submission ChemistryWorks counts for that student (an `Extra attempt` never counts), after teacher grading and regrades. No counted submission, or ungraded teacher-graded questions: `skipped_not_graded`. Released (`Released At` set): send `assignedGrade` and `draftGrade`. Graded, not released: `draftGrade` only. A student already `assigned` is never moved back to draft. Students match by lower-cased email against Classroom `userProfiles.emailAddress`, limited to the linked class's roster; a roster student not in the course is `skipped_not_on_roster` (including while coursework is still a draft), and Classroom students not on the roster are ignored. `action` values: `new`, `update`, `same`, `skipped_not_on_roster`, `skipped_not_graded`, `skipped_teacher_changed`.

**Overwrite guard.** A row is `skipped_teacher_changed` when any grade field we would write holds a value that is not what we last sent (`ClassroomSync.sentGrade`, or there is no row at all). Draft to assigned on release is an `update`, not a conflict. Only `syncGrades` with `overwrite: true` writes those rows.

`syncGrades` patches `StudentSubmissions` with an `updateMask`, about 100 ms apart, stops at about 25 seconds and returns `done: false` with a `cursor` (the index into the roster-ordered rows); the client calls again until `done`. A Classroom rate limit replies `classroom_rate_limited` with the `cursor`. Per student: `ProjectPermissionDenied` is `classroom_not_our_coursework`, a 403 is `classroom_not_teacher`, anything else `classroom_error`; a failure marks that row `failed` and the sync carries on. Each student gets a `ClassroomSync` row and a `Log` row; the tracker shows "Synced <time>".

Auto-sync: when `Classes.autoSyncClassroom` is true, `releaseAll` and `saveGrade({ release: true })` sync the affected students best-effort and add `classroomSync: { synced, failed }` to the reply; a failure never fails the release. Without Classroom the CSV export stays, formatted for Classroom's "Import grades". `test/unit/helpers/fake-classroom.mjs` is the shared fake service.

## Security notes

- Answer keys ship to the browser; client-side grading is part of the design. ChemistryWorks is a low and medium stakes formative tool (see `DEPLOYMENT.md`, Limitations).
- Never put test content or student input into `innerHTML`. Use `h()`, `richText()` or `textContent`. The only HTML strings allowed are output of helpers that escape their input (`formulaToHTML`, `configToHTML`, `chartSvg`, `escapeHtml`); `test/unit/xss.test.mjs` feeds hostile input to every one and to every type's `format`, `keyText` and `toPdf`, and checks every `html:` and `innerHTML` call site.
- CSP (`index.html` meta): `default-src 'self'`; scripts only from self, cdnjs and accounts.google.com; `connect-src` self, script.google.com, script.googleusercontent.com, oauth2.googleapis.com, raw.githubusercontent.com; styles from self, Google Fonts, cdnjs, accounts.google.com plus inline styles; `worker-src 'self'`; `manifest-src 'self'`. No inline scripts, so the version stamp is written by `npm run stamp:version`. E2E mocks must use a host the CSP allows (`https://script.google.com/...`).
- Backend: tokens verified on every student and admin call; `text_()` on every user cell; per-sender and global rate limits; constant-time `ADMIN_KEY` compare with lockout; error text never reaches the client.
- Admin identity: Google only. Demo admin is impossible when a client ID is configured.

## Theming and design

- `css/base.css` defines every colour, spacing, radius and motion value as a custom property on `:root`. Accents: `:root[data-accent="navy|blue|violet|teal|green|orange|rose"]`; dark mode: `:root[data-theme="dark"]`. Views never use raw hex (a unit test rejects it): use tokens (`--primary`, `--primary-soft`, `--primary-ink`, `--on-primary`, `--brand-teal` for fills and `--brand-teal-ink` for teal text, `--text-muted`, `--bg-sunken`, ...). Contrast of every text and surface pair is asserted by `test/unit/v2-contrast.test.mjs`; the axe scan (`test/e2e/a11y.test.mjs`) fails on any serious or critical issue in light and dark at 360 and 1366 px.
- Motion tokens: `--dur-fast` 120ms, `--dur-base` 200ms, `--dur-slow` 320ms, `--stagger-step` 40ms, `--dur-theme` 400ms, `--ease*`. No ad-hoc timings. Every animation is off under reduced motion (OS setting or the app switch); JS asks `prefersReducedMotion()` and nothing else.
- Design rules, brand and copy: `docs/DESIGN.md`. Copy is plain and short, sentence case, no exclamation marks, no emoji.
- Accessibility: icon-only buttons and links keep an `aria-label` when their text is hidden at narrow widths; scrollable table wrappers are focusable regions; every drag or pointer widget has a keyboard path (`test/e2e/a11y.test.mjs`).
- `index.html` loads `js/theme-boot.js` before first paint to apply the saved theme and accent.

## Tests

- `npm test`: unit tests (`test/unit/*.test.mjs`), including the Apps Script vm harness (`backend-*.test.mjs`), the type conformance and XSS suites, contrast, changelog and version-stamp checks.
- `npm run test:smoke`: boot smoke test (`test/e2e/smoke.test.mjs`): landing, admin, admin gate and the demo test load with no browser errors and leave the boot loader within 5 s. Run it after any change to `index.html`, `js/app.js` or an import list.
