# S08 — Performance overhaul (V5-11, client)

Backend half is B2. Behind `feature('perfStore')` until S08b finishes, then S08b turns it on.

## S08a — Data store + library
**Model:** sonnet · **After:** B2 · **Plan:** V5-11 "Why it is slow", "Client" · **Contract:** Data store
**Owns:** `js/lib/store.js` (new), `js/views/admin/library.js`, `js/lib/tests.js` (catalog loading), `data/tests/`
catalog file, `scripts/` (catalog generator if needed)

1. `store.js` to the contract (cache, background refresh, patch, optimistic with rollback + toast "Retry",
   subscribers, in-flight de-dupe, `AbortController` cancel on view leave, `sessionStorage` warm start).
2. Bundled tests: one catalog file with code, title, question count, points (generate it with a script and make
   `npm run validate:tests` check it's current); no per-test fetch to list.
3. Library on the store: published tests from one `listTests` (summary fields) — no `getTest`×N, no
   `getSubmissionCounts`, no full `getResults`. Delete / rename / duplicate / publish patch the list in place (row
   animates out/in); **draft delete makes no network request**; failures roll back with Retry. No skeleton after
   first load.
4. Unit `test/unit/v5-store.test.mjs` (de-dupe, rollback, subscribers, warm start). Update library e2e tests that
   waited on reloads.

## S08b — Grading, dashboard, classes, settings on the store
**Model:** sonnet · **After:** S08a · **Plan:** V5-11 "Client"
**Owns:** `js/views/admin/grading.js`, `js/views/admin/grade-by-question.js`, `js/views/admin/dashboard.js`,
`js/views/admin/classes.js`, `js/views/admin/bank.js`, `js/views/admin/settings.js`, `js/views/admin/shell.js` (no
refetch on section switch)

1. Grading: load results once per test with `getResults({ testCode })`; after save, patch the row from the write's
   returned `row`; refresh with `since`. Save → next student is instant. Bulk grade/release via `batch`.
2. Dashboard, classes, bank, settings read from store resources; sidebar section switch and back = no refetch.
3. Turn `perfStore` on in `js/config.js`. All existing admin/grading e2e green.

## S08c — Code splitting and lazy loading
**Model:** sonnet · **After:** S03b, S12z · **Plan:** V5-11 "App load"
**Owns:** `index.html`, `js/app.js`, `js/views/runner.js` → `js/views/runner/*.js`, `js/views/admin/builder.js` →
`js/views/admin/builder/*.js`, `js/lib/qtypes/v4-types.js`, `js/views/qtypes/index.js`, `js/lib/css-loader.js` (new)

1. Split `runner.js` and `builder.js` into modules (keep their public exports via re-export).
2. Lazy-load question-type UI modules by type (`await loadTypeUI(type)` before rendering a question; registry stays
   sync for already-loaded types) and game modes by id. Keep pure definitions eager (grading/validation need them).
3. `css-loader.js`: views request their stylesheets; `index.html` keeps only base + shell CSS eagerly.
4. Preload builder chunks on test hover in the library.
5. Full `npm run test:all` green (this touches everything — run it).

## S08d — Perf e2e test
**Model:** haiku · **After:** S08b, S08c · **Plan:** V5-11 "Targets"
**Owns:** `test/e2e/v5-perf.test.mjs`, small additions to `test/e2e/helpers.mjs` (a `gasDelayMs` option)

With every gas reply delayed 1500 ms, assert: draft delete removes the row in <100 ms and makes no gas request;
published delete removes the row in <300 ms; Library re-open (warm) shows rows in <300 ms; save grade → next student
<300 ms with exactly one gas request; switching sidebar section and back makes no gas request. Use
`page.waitForSelector` + `performance.now()` deltas, not sleeps.
