# S01 — CI and a green baseline (plan V6-01)

## S01a — CI workflow + boot smoke test
**Model:** sonnet · **After:** — · **Plan:** V6-01 "CI workflow"
**Owns:** `.github/workflows/ci.yml` (new), `.github/workflows/pages.yml`, `package.json` (`devDependencies`,
`scripts`), `package-lock.json` (new), `test/e2e/smoke.test.mjs` (new), `test/e2e/helpers.mjs` (launch only)

1. **Playwright:** add `playwright` as a devDependency, pinned to the version already installed here
   (`node -e "console.log(require('playwright/package.json').version)"`), and commit the lockfile.
   - `helpers.mjs` must still work in this container, where Chromium is at `/opt/pw-browsers/chromium`: honour
     `PLAYWRIGHT_BROWSERS_PATH` / an existing install, and don't hard-code the path.
2. **`ci.yml`:**
   - Triggers: `pull_request`, plus `push` to `main` and `claude/**`.
   - Jobs, all on Node 24:
     - `unit` (`npm test`)
     - `validate` (`npm run validate:tests`, plus `npm run build:catalog` and fail if `git diff --exit-code` shows a change)
     - `e2e` (`npx playwright install --with-deps chromium`, then `npm run test:e2e -- --test-reporter=spec`; upload failure screenshots if helpers save any)
     - `smoke`
   - Cache npm.
3. **`pages.yml`:** deploy only when CI succeeded for that commit (`workflow_run` on CI, `main`, conclusion success),
   or keep `needs:` jobs that run the same checks. Keep `workflow_dispatch`.
4. **`smoke.test.mjs`:**
   - Load `/` and fail on any console error or uncaught page error, or if the boot loader is still showing after 5 s.
   - Repeat for `/?admin=true` and `/?code=DEMOV5` (signed in with the demo).
   - Each case runs in under 10 s. This test exists to catch the 5.0.0 "stuck on loading" class of bug.
5. **`package.json`:** add `"test:smoke": "node --test test/e2e/smoke.test.mjs"`.
6. **Verify:** `npm test`, `npm run test:smoke`. Note in the report that the e2e job is **expected to fail until S01b merges**.

## S01b — Make every existing e2e test pass
**Model:** sonnet · **After:** — · **Plan:** V6-01 "Fix the failing e2e tests"
**Owns:** `test/e2e/*.test.mjs` except `smoke.test.mjs`, `test/e2e/helpers.mjs` (except launch), and small fixes in
`js/` where a failure is a real app bug

**Baseline on 2026-11-13** (`npm run test:e2e`): 29 of the first 42 tests failed, and the run hit a 15-minute timeout partway through `runner.test.mjs`. Each failure waits out a 30 s locator timeout. Set a shorter default action timeout in `helpers.mjs` (e.g. 5 s) so a broken suite fails fast. Most of them come from v5 changing the landing and
home and the tests never being updated. Examples:
- `landing.test.mjs` expects "Sign in with Google to Begin".
- `runner.test.mjs` waits for `[data-testid="code-input"]`, while the signed-in home now uses `home-code-input`.
- `admin.test.mjs` library expects "10 questions" on the card.
- `resilience.test.mjs` covers the Netlify channel, which is off on Pages.

1. Run the full suite once and list every failure in a table: test, cause, and whether it's a stale test or a real bug.
2. **Stale test:** update it to the current UI. Use testids, not copy, wherever a testid exists.
3. **Real bug:** fix it in `js/` with the smallest change, and add or keep the test that proves it.
   - Example: a submission path that loses data, a broken widget, a wrong score.
4. **Netlify tests:** these channels are removed in S08a. For now, mark the Netlify-only cases with a clear comment and
   keep them passing against the current code. **Don't delete them**; S08a removes them together with the code.
5. Don't add fixed sleeps. Where a test you touch has one, replace it with a wait for a condition.
6. Done = `npm run test:e2e` all green, twice in a row. Put the failure table in your report (it may be longer than 150 words).
