# S12 — Features: question tagging + Google Classroom (plan V6-09)

## S12a — Tags: local store, builder picker, Admin → Tags, importer
**Model:** sonnet · **After:** B3, S08c · **Plan:** V6-09 B, Decision 9 · **Contract:** V6 → Tags
**Owns:** `js/lib/tags.js` (new), `js/views/admin/tags.js` (new), `js/views/admin/builder/questions.js` (tag picker),
`js/views/admin/builder/publish.js` (send `tagDefs`), `js/lib/schema.js` (`tags` normalize/validate),
`js/lib/importers.js` (names → IDs), `js/lib/backup.js` (include local tags), `js/views/admin/shell.js` (`NAV_ITEMS`),
`css/tags.css` (new), `test/unit/tags.test.mjs`, `test/e2e/tags.test.mjs` (new)

1. **`tags.js`:**
   - The local store `cw:tags:<email>`: create, rename, recolour, delete. IDs are `tg_` + 6 base-36 characters.
   - `onSheet` marking.
   - `resolve(ids)`: local first, then Sheet tags from the store resource `tags` (`listTags`), following `mergedInto`.
   - `tagDefsFor(test)`: the definitions of every tag the test uses.
2. **Schema:** `tags` is an optional `string[]`, max 10, de-duplicated. Validation warns about unknown IDs.
3. **Builder:**
   - A picker per question, grouped into "Your tags" (local + yours on the Sheet) and "Shared tags" (other owners).
   - Type to search; Enter creates a local tag.
   - The question list can be filtered by tag; multi-select → "Apply tag".
   - Tag chips use the element-tile style with the tag colour, and their text passes contrast (`contrast.js`).
4. **Publish:** send `tagDefs`. On success, mark those tags `onSheet`. On `unknown_tag`, show which questions are
   affected.
5. **Admin → Tags:** three sections:
   - **Local:** edit and delete.
   - **On the Sheet, mine:** rename, recolour, merge, delete, with usage counts.
   - **Shared:** read-only, with the owner.
   
   Empty state: one sentence and one action.
6. **Importer:** tag **names** in imported JSON match local tags, then Sheet tags. A dialog lists the unmatched names
   and creates local tags for them.
7. **Backup:** backup/restore includes local tags.
8. **Tests:**
   - Unit: the store, `resolve`, `tagDefsFor`, schema, the importer.
   - E2E:
     1. Teacher A creates a tag, tags 3 questions and publishes.
     2. The Sheet (mock) has the tag.
     3. Teacher B sees it under Shared tags, uses it, and has no edit controls.
     4. A renames it, and B's builder shows the new name.

## S12b — Tags everywhere else
**Model:** sonnet · **After:** S12a, S02d · **Plan:** V6-09 B "Where tags appear"
**Owns:** `js/views/admin/grading.js`, `js/views/admin/grade-by-question.js`, `js/views/admin/hub/tracker.js`,
`js/views/results.js`, `js/views/feedback.js`, `js/views/profile.js`, `js/lib/modes/{mistakes,flashcards}.js` +
their option UI, `js/views/admin/library.js` (filter), `js/lib/tag-stats.js` (new), tests

1. **`tag-stats.js`:** per-tag earned/possible from graded results.
   - Counts released results only, wherever students see them.
   - Handles partial credit; teacher-graded items count once graded.
   - Questions with several tags count toward each tag.
2. **Grading and grade-by-question:** a tag filter plus "By tag" averages.
3. **Tracker:** class average per tag, plus a per-student breakdown in the student drawer.
4. **Results and feedback:** a "By topic" summary, only when released.
5. **Profile:** accuracy by tag across released results.
6. **Mistake review and Flashcards:** a tag filter.
7. **Library:** filter tests by tag.
8. **Names:** everywhere, names come from `tagIndex` (student side) or the `tags` resource (admin side). Never show raw
   IDs; a missing name shows "Unknown tag".
9. **Tests:**
   - Unit for `tag-stats` (released only, partial credit, several tags).
   - E2E: the rename appears in grading, the student's released results and the profile; an unreleased result shows
     no "By topic".

## S12c — Google Classroom UI
**Model:** sonnet · **After:** B4, S08c, S02d · **Plan:** V6-09 A, Decisions 7–8 · **Contract:** V6 → Google Classroom
**Owns:** `js/views/admin/classes.js` (link + roster import), `js/views/admin/hub/assign.js` (Post to Classroom),
`js/views/admin/hub/tracker.js` (sync column + button; coordinate: this runs in parallel with S12a, not S12b),
`js/views/admin/classroom-sync.js` (new preview dialog), `js/views/admin/stats.js` (Classroom-format CSV),
`css/classroom.css` (new), `test/e2e/classroom.test.mjs` (new), mock-backend helpers for the Classroom actions

1. **Classes:**
   - "Link to Google Classroom" → a course picker from `listClassroomCourses`, showing "Syncs as <syncAccount>".
   - "Import roster from Classroom".
   - An "Auto-sync grades on release" switch.
2. **Assign dialog:**
   - A "Post to Google Classroom" switch, shown only when the class is linked.
   - Delete asks whether to delete the coursework in Classroom too.
3. **Tracker and grading:** a "Sync grades" button opens the preview dialog:
   - A table of email, ChemistryWorks score, released yes/no, current Classroom grade, and action.
   - An "Overwrite Classroom changes" checkbox.
   - Sync runs in a loop on the cursor with progress, then shows a result summary.
   - The tracker shows "Synced <time>" per student, and failures with Retry.
4. **Error copy:** plain sentences for `classroom_not_our_coursework` ("This assignment was made in Classroom, not here.
   Post it from ChemistryWorks to sync grades.") and `classroom_not_teacher`.
5. **CSV:** the export in Google Classroom's "Import grades" format stays as the fallback.
6. **E2E** with a mocked backend:
   1. Link a course and import the roster.
   2. Assign with Post to Classroom.
   3. Grade 3 students, release 1.
   4. The preview shows assigned, draft and skip.
   5. Sync, and the tracker shows Synced.
   6. A teacher-changed grade is skipped unless Overwrite is ticked.
