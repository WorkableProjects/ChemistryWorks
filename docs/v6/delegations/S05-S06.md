# S05–S06 — One question-type system (plan V6-04)

Shared rules for all three:
- Move each built-in type to `js/lib/qtypes/<type>.js` (definition), `js/views/qtypes/<type>.js` (widget) and
  `js/views/admin/editors/<type>.js` (editor), per the V6 TypeDef contract.
- Behaviour must not change. `test/unit/qtype-fixtures.test.mjs` (S02c) and the existing question-type e2e tests must pass
  unchanged after each type moves.
- Remove each type's `case` from the four switches (`js/lib/grading.js`, `js/lib/schema.js`, `js/views/runner/widgets.js`,
  `js/views/admin/editors/core.js`) as you move it.

## S05 — Registry I: loaders, conformance test, simple types
**Model:** sonnet · **After:** S02c · **Contract:** V6 → TypeDef
**Owns:** `js/lib/qtypes/registry.js`, `js/lib/qtypes/v4-types.js` → `js/lib/qtypes/index.js` (rename, update every
importer), `js/views/qtypes/index.js`, new type files for mcq, multi, truefalse, numeric, formula, dropdown-style shared
helpers, `test/unit/qtype-conformance.test.mjs`, `test/e2e/qtype-conformance.test.mjs` (new)

1. **Loaders:** `loadTypeUI(type)` and `loadTypeEditor(type)` lazy loaders. Definitions stay statically imported, so
   grading and validation stay synchronous.
2. **Conformance tests**, for every registered type:
   - Unit: normalize → validate → grade with the fixtures → `format` → PDF/export text is not empty.
   - E2E: render in the runner and in every mode → answer → results → PDF view, with no console errors.
3. **Move** mcq, multi, truefalse, numeric and formula.
4. **CSS:** split the CSS by type for moved types (`css/qt-<type>.css`), loaded with the type UI.
