# S09 accessibility · S10 PWA · S11 deployment (plan V6-06, V6-07, V6-08)

## S09 — Accessibility (WCAG 2.1 AA)
**Model:** sonnet · **After:** S07, S08c · **Plan:** V6-06
**Owns:** `index.html` (`#app` aria), `js/app.js` (view announce + focus), small a11y fixes anywhere,
`package.json` (`axe-core` devDependency), `test/e2e/a11y.test.mjs` (new)

1. **App root:** remove `aria-live` from `#app`. Add one polite live region that announces the view title on navigation,
   and move focus to the view's `<h1>`, which gets `tabindex="-1"`.
2. **Drag-free input:** hotspot, categorize, ordering, matching, molbuild, ionicformula, bohr, graph plotting and the
   structure editor each get a way to answer without dragging. Pattern: focus an item, press Enter or Space to pick it
   up, use the arrow keys or Tab to reach a target, and press Enter to place it. Announce each step.
   Add an e2e test per type that answers by keyboard only.
3. **axe pass in `a11y.test.mjs`:** run `axe-core` in light and dark, at 360 px and 1366 px, on:
   - landing, home, profile, class page, notifications
   - the runner with DEMOV5, results, feedback
   - each game mode
   - admin dashboard, library, builder, grading, hub tracker, student view, Tags (if merged), settings and
     appearance, the sidebar collapsed and as a drawer
   
   Zero `serious` or `critical` issues allowed. Fix the causes; never disable rules.
4. **Manual checks**, listed in the report with pass/fail: 200% zoom with no lost content, reduced motion, and
   `prefers-contrast: more`.

## S10 — Offline and install (PWA)
**Model:** sonnet · **After:** S08b · **Plan:** V6-07
**Owns:** `manifest.webmanifest` (new), `sw.js` (new), `js/lib/sw-register.js` (new), `index.html` (manifest link +
register), `.github/workflows/pages.yml` (include the new files), `js/views/tools/banner.js` (offline copy),
`test/e2e/pwa.test.mjs` (new)

1. **Manifest:** name, short name, icons from `assets/brand/`, `start_url: "./"`, `scope: "./"`, theme colours from
   tokens (hard-coded values are allowed in the manifest only).
2. **`sw.js`:**
   - Precache the app shell, CSS, JS and fonts, listed by a small generated list (`scripts/build-sw-list.mjs`, checked
     in CI like the catalog). The cache name includes `SITE_VERSION`.
   - Tests and `changelog/` are network-first with a cache fallback.
   - Never cache Apps Script or Google requests.
   - Every path stays relative: Pages serves the site under `/ChemistryWorks/`.
3. **Update prompt:** when a new worker is waiting, show a toast "Update available — Reload". Don't auto-reload during
   a test. This fixes the old-version-label problem.
4. **Offline:** the banner reads "Offline — your answers are saved on this device". The submit outbox (S03) sends when
   back online.
5. **E2E:** after the first load, go offline: the landing and an already-opened test still work, an answer saves, and
   the submission goes to the outbox and sends when back online. A new version shows the update toast.

## S11 — Deployment automation
**Model:** sonnet · **After:** B2 · **Plan:** V6-08, Decision 4
**Owns:** `apps-script/.clasp.json.example` (new), `.claspignore` (new), `package.json` (scripts: `gas:push`,
`gas:deploy`), `.github/workflows/gas-deploy.yml` (new), `.github/workflows/pages.yml` (config overrides, publish
`docs/guide.md`), `js/config.js` (load `config.local.js` if present), `apps-script/Code.gs` (`setup()` checklist
only), `js/views/admin/platform.js` (checklist UI), `.gitignore`

1. **clasp:** `@google/clasp` as a devDependency. `npm run gas:push` pushes `apps-script/`. `npm run gas:deploy` runs
   `clasp deploy -i $GAS_DEPLOYMENT_ID`, updating the **existing** deployment so the URL never changes.
2. **`gas-deploy.yml`:**
   - `workflow_dispatch` only.
   - Writes `~/.clasprc.json` from the `CLASPRC_JSON` secret, then runs push, deploy and
     `curl "$GAS_WEB_APP_URL?action=ping"`. It fails unless the version equals the `VERSION` in `Code.gs`.
   - Exits early with a clear message when the secrets are missing.
3. **Config from repository variables:**
   - `pages.yml` writes `_site/js/config.local.js` from the repository variables `GAS_WEB_APP_URL`, `GOOGLE_CLIENT_ID`
     and `SHEET_URL`, only for the ones that are set.
   - `config.js` merges `config.local.js` when present. A missing file is not an error: use a dynamic import with a
     catch, or a `<script>` that sets `window.CHEMISTRYWORKS_CONFIG`; pick whichever works without a build step and
     under CSP.
   - Add `config.local.js` to `.gitignore`.
4. **Guide on Pages:** copy `docs/guide.md` into `_site/docs/guide.md` so the builder's fallback works on Pages.
5. **`setup()`:** also return a checklist: `ADMIN_KEY` set, `GOOGLE_CLIENT_ID` property set, `Admins` sheet has an
   owner, triggers installed, Classroom scopes granted (if the B4 code is present).
   Admin → Platform shows this checklist through `diag`/`whoami` data, with ticks.
6. **Tests:**
   - A unit test for the `config.local.js` merge.
   - A workflow lint: `actionlint` if available, otherwise YAML-parse in a unit test.
   - A unit test for the `setup()` checklist with the `vm` harness.
