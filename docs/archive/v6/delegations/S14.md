# S14 — Full-width student question view

## S14
**Model:** sonnet · **After:** S08b · **Plan:** `docs/v6/v6plan.md` → V6-11 (read it; it is the spec).

**Goal:** on wide screens the student question view fills the screen instead of a 760px column in the middle third.

**Owns:** `css/runner.css`, `css/modes.css`, `css/results.css`, `css/feedback.css`, the `--student-w` / `--student-gutter`
tokens in `css/base.css`, `css/qtypes.css` hotspot stage sizes, the runner question layout wrapper (`.q-split`), and a
`layout: 'split' | 'wide'` field on every `TypeDef` (default `split`; `wide` for matching, categorize, ordering, graph,
structure, lewis, molbuild, hotspot, ptable). Add `layout` to the V6 contracts in `docs/ARCHITECTURE.md` and `DESIGN.md`.

**Do:**
1. Replace every fixed cap listed in V6-11 with the shared tokens.
2. Prompt/explanation text keeps `max-width: 75ch`; answer areas take the full width.
3. Split layout ≥ 1200px; option columns (2 at ≥ 900px, 3 at ≥ 1400px) only when every option is ≤ 40 chars with no image.
4. Docked rail: content fills the remaining width. Footer spreads full width.
5. Below 760px the layout must be pixel-identical in behaviour to today. Do not touch `print.css` / `export.css`.

**Tests:** add `test/e2e/student-layout.test.mjs` with every check in V6-11 → Tests, and run the conformance test at
1920px. Attach screenshots (1920 / 1280 / 360, light + dark) to the report.

**Done when:** `npm run test:all` and `npm run validate:tests` pass, and the report includes test counts.
